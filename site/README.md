# Сайт Мастера «Корабля Времени»

*English version below.*

Локальный сайт, который помогает Мастеру готовиться к игре и вести её. План работы — [часть 3 основного плана](../time_ship_pf2_master_conversion_plan.md#Часть%203.%20Локальный%20сайт%20для%20Мастера).

## Главное правило

Сайт — проекция канона. Правила, существа, комнаты и предметы берутся из П1–П14 и словаря при каждом запуске. Своё у сайта только состояние партии. Если на сайте что-то не так, правится канон, а не сайт.

## Запуск

`start.bat` в корне репозитория. Нужен только Python 3 — без npm и pip. Сайт открывается на `http://127.0.0.1:8741/`.

`start.bat` показывает меню: открыть сайт (сервер запустится, если ещё не работает), перезапустить, остановить. Сервер работает в фоне без окна, поэтому меню можно закрыть, а сайт продолжит работать. Вывод сервера пишется в `saves/server.log`. Без меню: `start.bat open`, `restart`, `stop` или `status`; другой порт — `--port N`.

## Устройство

```text
канон (*.md) ──site_build.py──▶ данные (JSON, в git не хранятся)
                                        │
браузер ◀── site_server.py ◀────────────┘
   │  события ▲  SSE
   ▼          │
saves/*.jsonl (журнал событий)
```

- **`tools/site_build.py`** — сборщик. Разбирает markdown канона в JSON при каждом старте сервера и пишет отчёт о местах, которые не смог разобрать.
- **`tools/site_server.py`** — сервер на стандартной библиотеке Python. Раздаёт `site/`, принимает события, пишет их на диск и рассылает всем открытым окнам через SSE.
- **Состояние — журнал событий.** Каждое действие на сайте — событие; состояние — все события, применённые по порядку. Отмена — тоже событие: из журнала ничего не стирается. Сохранение — файл `saves/*.jsonl`, одно событие на строку.
- **Сохранения.** Текущая игра хранится в `saves/current.jsonl`. «Новая игра» и импорт сначала переносят текущий файл в `saves/archive/`. Если сервер остановился посреди записи, оборванная последняя строка при запуске отбрасывается, а сайт предупреждает об этом.
- **Фронтенд** — Preact + htm одним файлом в `site/vendor/`, без сборки.
- **Изображения** — `site/img/<id>.*`. Файла нет — карточка без картинки.
- **Ссылки** — якоря в формате Obsidian (`файл.md#Заголовок%20раздела`), как в каноне.

## Данные канона

При каждом старте сервер запускает `tools/site_build.py`, и тот пишет в `site/data/` (в git не хранится):

- **`canon.json`** — канон для сайта. `docs` — файлы по порядку: П1–П14 и словарь (`kind: "canon"`), затем справочные файлы, на которые ссылается канон (`"companion"`): лестница угроз, карта, реестр открытых вопросов, журнал расхождений. У файла `id` (`p1`…`p14`, `slovar_terminov`, …), полный и короткий заголовок и `sections` — разделы по порядку: `key`, `title`, `level`, `number` («3.4» или `null`), `parent` (ключ родителя), `line`, `text` (markdown раздела без подразделов). `links` — все ссылки между файлами сайта: `[из файла, из раздела, в файл, в раздел]`. `boundaries` — границы канона: раздел П1 «Границы канона» (`doc`, `key`) и `items` — разделы, на которые он ссылается, с тем, что канон там не задаёт (`doc`, `key`, `what`). `terms` — термины PF2 для подсказок из словаря, раздел 8: `conditions` (подраздел «Состояния») и `traits` («Признаки»), у каждого `key` подраздела и `items` — `name`, `en` (английское название или `null`), `text` (что делает, markdown), `href` (ссылка на AoN или `null`), `own` (свой признак приключения). `creatures` — существа из блоков характеристик П9 и П11 (см. «Существа» ниже), `hazards` — опасности из блоков П7 (см. «Опасности»), `npcs` — карточки НПС П8 (см. «НПС»), `items` — предметы П12 со слоями знаний (см. «Предметы»), `state` — схема состояния мира из листа Мастера П2 (см. «Состояние мира»), `rooms` — комнаты П13 (см. «Комнаты»), `map` — граф карты Корабля (см. «Карта»).
- **`build_report.json`** — отчёт сборщика: сводка по файлам, находки и `hidden` — разделы, которых не показывает ни одна карточка (см. ниже). Его показывает страница «Инструменты → Отчёт сборщика».

Ключ раздела — якорь Obsidian: текст заголовка без двоеточий. Ссылка канона `файл.md#якорь` поэтому находит раздел без таблиц соответствия. Повторяющиеся заголовки («Тактика» у каждого НПС) получают ключи «Тактика (2)», «Тактика (3)»: ссылкой, как и в Obsidian, достижим только первый. Ссылка на такой повтор — предупреждение в отчёте. Ссылка без цели или на файл, которого нет на сайте, — ошибка. Источники и планы (OCR, план доведения) сайт не показывает, ссылки на них ошибкой не считаются.

Если сборка упала, `canon.json` удаляется: сайт скорее покажет, что канона нет, чем покажет устаревший. Проверка без записи файлов: `python tools/site_build.py --check` — две сборки подряд должны совпасть байт в байт, а в отчёте не должно быть ошибок.

**Разделы вне карточек.** Карточка показывает только свои разделы, и то, что канон пишет о существе или предмете в другом месте того же файла, видно лишь в читалке. `tools/site_coverage.py` перечисляет разделы с текстом в файлах, где лежат сами карточки (П7, П8, П9, П11, П12; файл, откуда карточка только сворачивает раздел, как П5, не перечисляется), которых не показывает ни одна карточка: у каждого `doc`, `key`, `title`, `line`, `top` и `top_title` (раздел второго уровня, для группировки), `size` (знаков текста) и `linked` — на раздел ссылается карточка или страница (части тела Пса и Постчеловека в П12, законы мира П7, раздел 11). Показанным считается то же, что выводят страницы: блок существа и его `info` со всем, что под ними, и текст НПС в П11, если у блока нет своего вступления; раздел опасности и предмета со всем, что под ним, и их разделы «Подробно» (у предмета — и «Общие правила» его раздела); карточка НПС в П8 и разделы её «Подробно» со всем, что под ними. Это не находки, а список для сверки: большая часть — общие правила и таблицы. Если страница начнёт показывать больше или меньше, правится и `site_coverage.py`. `python tools/site_build.py --hidden` печатает список в консоль.

## Читалка

«Канон → Пункты» показывает файл целиком с оглавлением (заголовки уровней 2–3). Адрес раздела — `#/canon/read/<файл>/<ключ раздела>`, например `#/canon/read/p8/10.2.%20Организация%20Культа`; без раздела — начало файла, без файла — список файлов и границ канона. Ссылки канона ведут на те же адреса, ссылки на файлы вне сайта (источники, планы) показаны пунктиром без перехода.

- **`site/canon.js`** загружает `canon.json` один раз на всё окно; в нём же адреса разделов и перевод ссылок канона в адреса сайта — ими будут пользоваться и карточки следующих подшагов.
- **`site/markdown.js`** — markdown канона в HTML, ровно в том объёме, что использует канон (как в Obsidian: одиночный перенос строки остаётся переносом). Проверка — отрисовать все разделы и поискать остатки разметки: `**`, `](`, строки таблиц.
- **Границы канона.** Раздел, на который ссылается П1 «Границы канона», получает метку «канон не задаёт: …» со ссылкой на П1. Строка списка в П1 — по образцу `- что — [ссылка](файл.md#раздел)`; иную сборщик отметит предупреждением. Новая граница добавляется только в П1.

## Поиск

Строка поиска — в шапке на любой странице, Ctrl+K ставит в неё курсор. Ввод открывает «Канон → Поиск» с адресом `#/canon/search/<запрос>`; дальнейший ввод заменяет адрес, а не добавляет новый, поэтому «Назад» уходит с поиска за один шаг.

- **`site/search.js`** строит индекс в браузере при первом поиске: заголовок и текст каждого раздела без разметки. Канон — около миллиона символов: индекс собирается за ~60 мс, запрос проходит за 2–3 мс, поэтому сервер в поиске не участвует.
- Раздел находится, если в нём есть все слова запроса — в заголовке или в тексте; фраза в кавычках ищется целиком. Регистр и ё/е не важны, слово находится и внутри длинных слов («кристалл» → «Кристалла»): морфологии нет, и префикс её заменяет.
- Порядок: сначала канон, потом справочные файлы (действует текст пунктов); затем разделы, где слово стоит в заголовке; дальше — по числу совпадений в тексте и по порядку канона.
- Выдача показывает путь раздела — файл и заголовки над ним: «Тактика» есть у каждого НПС, — кусок текста у первого совпадения с подсветкой и фильтр по файлам.
- Переход из выдачи ведёт на `#/canon/read/<файл>/<ключ>?q=<запрос>`: читалка подсвечивает запрос в этом разделе и прокручивает к первому совпадению. Слово, разрезанное разметкой (половина жирным), в читалке не подсвечивается.

## Подсказки терминов

Состояния и признаки PF2 из словаря подчёркнуты пунктиром; при наведении — подсказка: название, английское название, что делает, ссылки на Archives of Nethys и на словарь. Подсказка не закрывается, пока указатель на термине или на ней самой, поэтому ссылки в ней можно нажать. Щелчок по термину закрепляет подсказку (так она работает и на сенсорном экране); щелчок в другом месте, Escape, прокрутка или переход закрывают её.

- **`site/terms.js`** размечает термины в HTML, который вернул `renderMarkdown`: `<span class="term" data-term="c:3">`, где `c` — состояние, `t` — признак, а число — номер в `canon.terms`. Размечать можно любой текст канона, так что карточкам следующих подшагов достаточно вызвать `markTermsHtml`.
- **Состояния** отмечаются по всему тексту и в склонённых формах: окончания подбираются по концу слова — краткое и полное причастие («оглушён», «оглушено», «оглушённый»), существительное («истощение», «обречённость», «тошноту»), значение после названия («испуган 1»). У «умирает» и «ранен» формы заданы отдельно: «умирающий» общее правило не находит, а «раненых» и «ранение» — обычные слова. Синонимы из раздела 2 словаря — «усталость», «продолжительное кровотечение» — тоже отмечаются.
- **Признаки** отмечаются только в строке «**Признаки:**» блока характеристик: как обычные слова «огонь», «средний» и «животное» встречаются везде.
- Внутри ссылок, кода и курсива терминов нет: курсивом пишутся заклинания (*Замедление* — не «замедлен»). В словаре термины не отмечаются: там они и определены.
- Разметка всех разделов канона занимает ~150 мс при первом открытии каждого файла; найдено около 280 терминов, все 45 признаков словаря встречаются в строках признаков.

## Существа

Блоки характеристик П9 и П11 разбирает `tools/site_creatures.py` (его вызывает сборщик). Блок целиком лежит в одном разделе — это проверяет `tails_check.py` — и объявляет уровень: заголовком «… — Существо N», первой строкой «**Существо N**» или, у профиля Оболочки, строкой «**Числовая калибровка:** N-й уровень».

Разбирается только то, чего сайт не прочтёт из markdown; остальное остаётся markdown и показывается как написано. Поля существа в `canon.json`:

- `id` — латиница из имени («Хрустальный Паук» → `khrustalnyy-pauk`), имя файла картинки `site/img/<id>.*`; совпадение `id` — ошибка сборщика.
- `doc`, `key` — раздел блока; `home` — раздел о существе целиком: в П11 блок — подраздел НПС, и `home` — его родитель.
- `name`, `level`, `note` (приписка после уровня: «рой»), `budget` (`false` у профиля, который не считается существом для бюджета столкновения).
- `traits` — строка «**Признаки:**»; `classification`, `role` — строки «Классификация» и «Роль», если есть; `aon` — ссылка на официальный блок (`title`, `href`), если есть.
- `intro` — описание до блока (в П11 — текст `home`), `body` — сам блок без уровня, ссылки и строк шапки.
- `numbers` — числа для сцены: `perception`, `ac`, `fort`, `ref`, `will`, `hp`; `notes.ac` — оговорка к КБ («22, когда броня сломана»). Число, которое не разобралось, — предупреждение в отчёте.
- `abilities` — подразделы блока до первого «Поведения» или «Изменений»; `info` — остальные подразделы и, в П11, соседние разделы НПС («Тактика», «Переговоры»). Если в разделе над блоком есть подраздел «Общие правила» (П9, 22.1 — пленники Склада), он идёт в `info` первым у каждого блока этого раздела, с заголовком «Общие правила: <раздел>». У каждого `key`, `title` и `actions` («1 действие», «реакция» или `null`).
- `parts` — слои знаний частей тела из П12 (`doc`, `key`, `check`, `layers`, как у предмета) или `null`; есть у Механического Пса и Постчеловека, см. «Предметы».

**Страница «Канон → Существа»** (`site/pages/creatures.js`). `#/canon/creatures` — таблица всех существ по пунктам: уровень, признаки, КБ, ПЗ, Восприятие и спасброски; фильтр по имени и признаку. У профиля Оболочки уровень отмечен звёздочкой: для бюджета столкновения он не считается. `#/canon/creatures/<id>` — карточка: уровень, признаки плашками с подсказками, классификация и роль, описание, блок в рамке, умения с числом действий и свёрнутые «Сведения» — поведение, знания, трофеи, а в П11 тактика и переговоры. У Пса и Постчеловека после них — «Части тела: слои знаний» с отметками «знают», как на карточке предмета; отметка — то же событие `item-layer` с `id` существа. Внизу — переход в пункт к разделу `home` и ссылка на официальный блок AoN. В читалке у заголовка каждого блока есть ссылка «карточка».

## Опасности

Блоки опасностей П7 разбирает `tools/site_hazards.py` (его вызывает сборщик) — так же, как существ: разбирается только то, чего сайт не прочтёт из markdown. Блок — раздел с уровнем в заголовке: «Взрыв часов 41 — Опасность 8», у комплексной «… — Опасность 8 (комплексная)». Реакции и действия — его подразделы, последний — «Обоснование». Поля опасности в `canon.json`:

- `id` — латиница из имени, имя файла картинки `site/img/<id>.*`; совпадение `id` с другой опасностью или с существом — ошибка сборщика.
- `doc`, `key` — раздел блока; `name`, `level`, `complex` (комплексная ли).
- `traits` — строка «**Признаки:**»; `stealth` — Скрытность как записана: «+18», «КС 23» или `null` для «—».
- `saves` — спасброски из правил блока по порядку, без повторов: `save` («Рефлекс», «Стойкость», «Воля») и `dc`.
- `numbers` — числа для сцены, только те, что блок задаёт: `stealth` (модификатор для инициативы, если Скрытность записана как «+N»), `attack`, `ac`, `fort`, `ref`, `hardness`, `hp`, `bt` (Предел поломки). Защита есть только у опасностей, которые можно атаковать.
- `body` — блок без заголовка и строки признаков.
- `abilities` — подразделы до «Обоснования» (реакции, циклы действий, «Степени обнаружения»); `info` — «Обоснование». У каждого `key`, `title` и `actions` («реакция» или `null`).
- `more` — разделы П7 из абзаца «**Подробно**» в конце собственного текста блока, `[{doc, key}]`: где и как опасность вступает в игру (6.1 для энергетических дверей, 8.2 для часов). Абзац в `body` не входит; ссылка без цели — ошибка сборщика. Без абзаца `more` пуст.

Нет строки признаков или Скрытности, нет подраздела с правилами — предупреждение в отчёте.

**Страница «Канон → Опасности»** (`site/pages/hazards.js`). `#/canon/hazards` — таблица 12 опасностей: признаки, уровень, простая или комплексная, Скрытность и проверка («Рефлекс КС 20», у молниевого контура «атака +20»); фильтр по названию и признаку. Под таблицей — законы мира без блока ([П7, раздел 11](../korabl_vremeni_punkt_7_hazards.md#11.%20Законы%20мира%20без%20блока%20характеристик)) ссылками в читалку. `#/canon/hazards/<id>` — карточка: вид и уровень, признаки плашками с подсказками, блок в рамке, реакции и циклы действий с плашкой «реакция», свёрнутое «Обоснование», затем «Подробно» — разделы `more` складками, как у карточки НПС, переход в П7. В читалке у заголовка каждого блока есть ссылка «карточка». Части, общие для карточек существ, опасностей и НПС, — в `site/card.js`, в том числе складки «Подробно» (`More`).


## НПС

Короткие карточки НПС и фракций [П8, раздел 20](../korabl_vremeni_punkt_8_fraktsii_i_npc.md#20.%20Карточки%20НПС%20/%20фракций) разбирает `tools/site_npcs.py` (его вызывает сборщик). Карточка — подраздел «20.2. Сарежейн» из пунктов «- **Поле:** текст». Набор полей у карточек разный — у погибших операторов их меньше, у семьи часть склеена, — поэтому поля хранятся как записаны. Последний пункт, «**Подробно:**», ведёт ссылками к полным разделам: НПС в П8 и его блоку в П11 или П9. Поля НПС в `canon.json`:

- `id` — латиница из имени, имя файла картинки; совпасть он может только с `id` своего существа — тогда одна картинка служит обеим карточкам. Иное совпадение — ошибка сборщика.
- `doc`, `key` — раздел карточки; `name`.
- `fields` — поля по порядку: `label` и `text` (markdown).
- `more` — разделы из «Подробно» (`doc`, `key`); ссылка, не нашедшая раздел, — ошибка сборщика.
- `start` — номер комнаты, если поле «Старт» — просто номер («19.»), иначе `null`: весь Корабль, ещё не создан, мёртв, группа без места. Такого НПС Мастер ставит на карту сам.
- `creature` — `id` существа, если один из разделов «Подробно» — его блок или раздел `home`; иначе `null`.

Нет полей или строки «Подробно» — предупреждение в отчёте.

**Страница «Канон → НПС»** (`site/pages/npcs.js`). `#/canon/npcs` — таблица 11 НПС и фракций: тип, старт, главная цель и уровень блока со ссылкой на карточку существа; фильтр по имени и типу. `#/canon/npcs/<id>` — карточка: поля П8 двумя колонками со ссылками и подсказками, уровень блока в шапке, кнопки к карточке существа и к самой карточке в П8. Ниже — «Подробно»: каждый раздел строки «Подробно» свёрнутой складкой, как «Сведения» у существ, с заголовком «П8 · 14.4. … · Сарежейн» (у раздела без номера — путь до ближайшего раздела с номером) и ссылкой в читалку внутри; раздел блока существа складкой не повторяется. Все разделы, где канон пишет об одном НПС, собирает сама строка «Подробно» в П8: сайт их по именам не ищет. Карточка существа, чей блок служит НПС, получает кнопку «НПС: …» обратно. Картинка — `site/img/<id>.*`, а если её нет — картинка существа: так у Культа картинка Служителя Парадокса. В читалке у заголовка каждой карточки П8 есть ссылка «карточка».


## Предметы

Предметы П12 со слоями знаний разбирает `tools/site_items.py` (его вызывает сборщик). Блок слоёв записан по образцу [П12, раздел 24.4](../korabl_vremeni_punkt_12_predmety_sokrovishcha_i_ekonomika.md#Блок%20слоёв%20у%20предмета): строка «**Слои знаний.**» с действием, навыком и КС, затем таблица степеней. Блок стоит в конце раздела предмета или в его последнем подразделе. Предмет — ближайший раздел, свой или выше, чья первая строка — шапка предмета: «**Категории:** …», «**Категория: …**» или «**Предмет N-го уровня, …**»; раздел без шапки сам считается предметом. Раздел 24.4 — образец, не предмет. Механический Пёс и Постчеловек из раздела 18 — не предметы: их блоки — для частей тела существа, а канон называет их встроенными системами и частями тела. Их слои уходят в поле `parts` одноимённого существа. Раздела нет — предупреждение сборщика, существа нет — ошибка. Поля предмета в `canon.json`:

- `id` — латиница из имени, имя файла картинки; совпасть может только с существом того же имени (Челюсть) — тогда картинка общая. Иное совпадение — ошибка сборщика.
- `doc`, `key` — раздел предмета; `group` — его раздел верхнего уровня («18. Трофейная технология существ будущего»); `name`.
- `check` — строка блока после «Слои знаний.»: действие, навык, КС и оговорки (markdown).
- `layers` — строки таблицы по порядку: `label` (как записана: «Успех, Ремесло КС 15»), `degree` («Без проверки», «Успех», «Критический успех», «Критический провал», «Не узнаётся») и `text`. `label` — ключ отметки «игроки знают», поэтому повтор строки — ошибка сборщика.
- `block` — раздел, где стоит блок; `rest` — текст этого раздела без блока, чтобы карточка не показывала таблицу дважды, и без абзаца «**Подробно**».
- `more` — `[{doc, key}]`: подраздел «Общие правила» раздела второго уровня над предметом (18 — трофейная технология, 20 — Библиотека), затем ссылки абзаца «**Подробно**» из раздела блока — где ещё канон пишет о предмете (П5 для Кристалла и Браслета, раздел 25 для репликатора). Ссылка без цели — ошибка сборщика.

Два блока у одного предмета — ошибка, блок без таблицы и непонятная степень — предупреждения.

**Страница «Канон → Предметы»** (`site/pages/items.js`). `#/canon/items` — таблица 29 предметов в порядке П12: сколько строк слоёв игроки уже знают, проверка и раздел П12; фильтр по названию, разделу и навыку. `#/canon/items/<id>` — карточка: сначала «Слои знаний» — строка проверки и таблица, где у каждой строки отметка «знают», затем описание предмета из канона без таблицы слоёв и «Подробно» — разделы `more` складками, как у НПС и опасностей. Предмет, который одновременно существо (Челюсть), получает кнопку «Существо: …», а его карточка существа — «Предмет: …». Отметка на строке «Критический провал» значит, что игроки поверили ложному выводу; эта строка выделена цветом.

Отметка — состояние партии: событие `item-layer` `{ item, name, row, known }` (срез `itemLayers`), поэтому она попадает в журнал, отменяется и видна во всех окнах. Ключ строки — `label` из канона: если строку в каноне переписать, старая отметка на неё больше не ложится. В читалке у заголовка каждого предмета есть ссылка «карточка».


## Состояние мира

Схему страницы «Игра → Состояние мира» сборщик берёт из [П2, «Минимальный лист состояния Мастера»](../korabl_vremeni_punkt_2_struktura_i_zavisimosti.md#Минимальный%20лист%20состояния%20Мастера); разбор — `tools/site_state.py`. Лист — блок текста: первая строка — заголовок листа, дальше группы. Группа — строка заглавными буквами, под ней поля «Поле: значение». Вид поля задаёт значение, как в легенде над листом:

- варианты через « / » — выбор одного (`choice`, `options`);
- прочерк из пяти «_» — число (`number`, `max: null`), `_____ / 17` — число с пределом (`max: 17`);
- прочерк из десяти «_» — короткая запись (`text`, `long: false`), длиннее — список или журнал (`long: true`);
- строка из одного прочерка — свободная запись всей группы: у поля `label: null`.

У поля `key` — «ГРУППА · Поле», а у свободной записи — название группы; это ключ событий страницы, поэтому переименованное в каноне поле теряет прежнее значение. `rooms` — номера комнат из названия группы, поля и вариантов: по ним страница комнаты покажет свои поля. Таблица над листом даёт каждой группе `more` — разделы П2, часть 3, где группа описана подробно. Подраздел под листом, «Исходное состояние Корабля», — таблица «Группа | Поле | На старте | Откуда»: из неё поле получает `start` (вариант, число или строка; `null`, если строки нет — такое поле начинается пустым) и `source` (markdown колонки «Откуда»). Группа пишется в первой строке своих полей, «—» вместо поля — свободная запись группы. В `canon.json` `state` — это `doc`, `key` (раздел листа), `start_key` (подраздел исходного состояния или `null`) и `groups` по порядку: `title`, `more`, `fields`.

Значение не по легенде, число вне комнат 1–41, группа без полей или без ссылок в таблице, нет подраздела исходного состояния, исходное значение без источника — предупреждения; поле дважды, группа таблицы, которой нет в листе, ссылка без цели, исходное значение для поля, которого нет, не подходящее полю или записанное дважды, — ошибки.

**Страница «Игра → Состояние мира»** (`site/pages/world.js`). `#/game/world` — группы листа панелями, у каждой ссылки на её разделы П2. Панели раскладывает `site/masonry.js`: столько колонок, сколько помещается по 420 px, и каждая следующая панель уходит в самую короткую колонку, поэтому колонки кончаются почти вровень. Раскладка пересчитывается целиком при смене числа колонок или фильтре; если панель выросла или уменьшилась, она и все панели до неё остаются на месте, а заново раскладываются только следующие. Поле начинается с исходного значения канона: оно показано приглушённо, а подсказка у названия поля говорит, откуда оно. Поле управляется по виду: выбор — кнопками вариантов, число — полем с пределом, запись — полем, высота которого идёт за текстом: пустое — одна строка, заполненное — столько строк, сколько занимает текст с переносами. Короткая запись стоит рядом с названием, длинная — во всю ширину панели. Перед каждой раскладкой панелей `site/masonry.js` шлёт событие `masonry-measure`, и записи подгоняют высоту под новую ширину колонки до замера. Изменённое партией поле подсвечено, и у него есть кнопка «исходное»; щелчок по отмеченному варианту тоже возвращает исходное, а у поля без исходного снимает отметку. Фильтр ищет по полю и группе, а число — ещё и по комнатам поля: «41» показывает всё о комнате 41.

Изменение — состояние партии: событие `world-set` `{ field, value }` (срез `world`, ключ — `key` поля); `value: null` убирает изменение, и поле снова такое, как на старте. Значение, равное исходному, тоже уходит как `null`, а `""` — запись, которую очистили намеренно. Исходные значения в журнал не пишутся: их даёт канон, поэтому правка таблицы в П2 меняет все поля, которых партия не касалась. Выбор уходит сразу, число и запись — когда поле теряет фокус, по Enter (у длинной записи — Ctrl+Enter), Escape возвращает прежнее; так в журнал попадает одна запись на изменение. Число ограничено нулём и пределом поля. Значения полей, которых в листе больше нет (поле переименовали в каноне), страница показывает внизу отдельным блоком, и их можно убрать.


## Комнаты

Комнаты сборщик берёт из [П13](../korabl_vremeni_punkt_13_room_by_room_pf2_overlay.md#Комнаты%201–41): 41 раздел «N. Название» под «Комнаты 1–41»; разбор — `tools/site_rooms.py`. У комнаты `number`, `id` (`komnata-N`, имя картинки), `doc`, `key` (раздел П13), `title` без номера и связи, записанные в самом каноне, а не угаданные по названию:

- `creatures`, `hazards`, `items`, `npcs` — id карточек из ссылок строки «**Связанные системы:**» комнаты, в порядке строки. Ссылка на раздел даёт каждую карточку, чей раздел — этот или лежит под ним: П9, 22 даёт одиннадцать пленников Склада, П12, 19 — шесть экспонатов Музея; существо находится и по разделу своего НПС в П11, а НПС — по карточке П8, 20 или по разделу своей строки «Подробно». Ссылка на файл целиком карточек не даёт;
- `neighbours` — номера комнат, на которые ссылается та же строка;
- `start` — у комнаты есть строка «**Старт группы:**»: здесь группа начинает приключение ([реестр, тема 1.15](../otkrytye_voprosy.md#1.15.%20Где%20группа%20начинает%20приключение)). Такая строка должна быть ровно у одной комнаты, иначе ошибка сборщика;
- `outside` — блок «**Случайные встречи**» комнаты говорит, что таблица П10 здесь не проверяется или не генерируется: комната вне внутреннего пространства Корабля. Сейчас это ферма (1), Подвал (2), Подземная река (38) и 41. Блок, который говорит другое, — предупреждение сборщика;
- `fields` — ключи полей листа П2: сначала те, что текст комнаты называет в обратных кавычках как `ГРУППА · Поле`, затем те, в названии которых стоит номер комнаты. Триггер «условие → следствие» может назвать в одних кавычках несколько полей: `ГРУППА · Поле = а + ГРУППА · Поле = б → ГРУППА · Поле = в; …` — значение после «=» кончается на «;», «,», «+» или «→»;
- `source` — `{ line, parts }` из [исходника](../korabl_vremeni_ocr.md), или `null`, если комнаты в исходнике нет; разбор — `tools/site_room_source.py`. Часть — `{ text }` (markdown исходника как есть), `{ heading }` (свой подзаголовок комнаты: сейчас только таблица пульта 19) или `{ cut, kind, id, line }` (вклеенный блок карточки, заменён ссылкой). Таблица `BLOCKS` модуля задаёт «заголовок исходника → карточка»; исходник пишет заголовки по-своему («Хрустальные пауки» — «Хрустальный Паук»), карточку не угадывают. Блок существа кончается на строке `**КБ …` и её пунктах; блок предмета (заголовок курсивом) — на курсивных абзацах и курсивных строках списков. После блока текст комнаты может идти без заголовка.

Поле, которого нет в листе, значение после «=», которого поле не принимает, ссылка связей без цели, неизвестный заголовок внутри комнаты исходника и блок без карточки — ошибки сборщика; комната без строки связей, блок, чью карточку строка связей комнаты не называет, и комната без исходника — предупреждения. Вырезанные блоки сборщик кладёт в отчёт `source_cuts`. Запрет на флаги комнат со своими именами (`рост_8_футы`), на состояния в обратных кавычках без поля листа (`веко закрыто`) и на упоминания пунктов и комнат без ссылки в строке связей держит `tools/tails_check.py`.

**Страница «Игра → Комнаты»** (`site/pages/rooms.js`). `#/game/rooms` — таблица 41 комнаты: сколько у неё существ, НПС, опасностей и предметов (имена — в подсказке у числа), сколько её полей листа партия изменила и есть ли заметка; фильтр по названию и карточке, а число — по номеру комнаты. `#/game/rooms/<номер>` — комната: переходы к соседним по номеру и к комнатам её строки связей, слева — блок «Исходник» (`source`) над надстройкой П13 как её пишет канон и картинка `site/img/komnata-N.*`, справа — карточки по видам (у существ и опасностей — уровень), заметка Мастера и поля листа по группам. Поля показаны теми же панелями, что на странице «Состояние мира» (`Group` из `site/pages/world.js`): те же кнопки, подсветка изменённого, «исходное» и событие `world-set`, поэтому поле, изменённое в комнате, изменено и в листе. Когда страница уже 1000 px, всё идёт одной колонкой: сначала исходник и надстройка, потом карточки, заметка и поля.

Заметка — состояние партии: событие `room-note` `{ room, text }` (срез `roomNotes`, ключ — номер комнаты, как у картинки, чтобы переименование комнаты не теряло заметку); `text: null` убирает заметку. Как длинная запись листа, она сохраняется, когда уходишь из поля, или по Ctrl+Enter, а Enter переносит строку.

**«Где встречается»** (`WhereFound` из `site/card.js`) — обратные ссылки: карточки существ, опасностей, предметов и НПС перечисляют комнаты П13, чья строка связей их называет, по номеру комнаты; ссылка ведёт на страницу комнаты. Ниже — строки случайных встреч П10, чья карточка называет карточку в строке связей, со ссылкой на раздел карточки встречи; у существа — его роль: «состав», вариант сцены по названию или обе, и с какого уровня строка доступна. Строятся они на странице из `canon.rooms` и `canon.encounters`, отдельного поля в `canon.json` нет. Карточку, которую не называет ни комната, ни строка встреч, блок так и помечает; сейчас таких нет.

## Случайные встречи

Таблицу случайных встреч сборщик берёт из [П10](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md); разбор — `tools/site_encounters.py`. В `canon.json` это `encounters`: `doc`, `key` (раздел [4.2](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md#4.2.%20Единая%20накопительная%20таблица%201–12) с таблицей), `cards` (раздел 12 с карточками), `outside` (раздел 11, сцены вне таблицы), `procedure` (раздел 2, проверки), `stop` (раздел 18, отделённый Корабль прекращает проверки), `levels` — `[{level, die}]` из таблицы [раздела 3](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md#3.%20Принцип%20накопительной%20таблицы): на 3-м уровне d6, на 4-м d12 — и `rows`, по строке на результат:

- `number`, `level` (с какого уровня доступна), `name`; `composition`, `type`, `chrono`, `repeat`, `reaction`, `signs`, `motive` — столбцы таблицы как написаны; `count` — кубик состава из начала столбца «Состав» («1d6», «2») или `null`, если состав не число (№ 12);
- `key` — раздел карточки «№ N. Название» в разделе 12;
- `creatures`, `hazards`, `items`, `npcs`, `rooms` — карточки и комнаты из ссылок строки «**Связанные системы:**» карточки, разобранные так же, как у комнат. Строка делится по «;», и текст части вне ссылок — её роль: «состав» кладёт существ в `main` — обычный состав строки, «вариант «…»» — в `creatures` варианта с этим названием. Часть из одних ссылок берёт роль предыдущей: «трофеи — [18.1]; [18.2]»;
- `variants` — абзацы карточки «**Вариант сцены — название.** …»: `name`, `text` и `creatures`;
- `fields` — поля листа П2, которые карточка называет как `ГРУППА · Поле`: у № 5 — число контрабандистов на свободе, у № 11 — Постчеловек.

Строка таблицы не из десяти столбцов, строка без карточки и карточка без строки, номера не подряд, кубик уровня, который не покрывает ровно доступные строки, ссылка связей без цели, неизвестное поле листа, значение, которого поле не принимает, и вариант в роли, которого у карточки нет, — ошибки сборщика; вариант, чьих существ строка связей не называет, и название карточки, отличное от строки таблицы, — предупреждения. Строку связей у каждой карточки проверяет и `tools/tails_check.py`.

**Страница «Игра → Случайные встречи»** (`site/pages/encounters.js`, состояние и правила — `site/encounters.js`). Счётчик идёт по трекеру ходов: ход в Корабле — шаг, шумный ход — ещё шаг ([П3, раздел 9](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#9.%20Шум)), пока отмечено «группа вне Корабля», ходы шагов не дают ([П10, раздел 2](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md#2.%20Что%20сохраняется%20из%20исходника)). Проверка — раз в 2 шага, раз в 4, если по листу `СТЫКОВКА 39 / ВРЕМЯ 41 · Кристалл 39 = снят` или `Агрегат 39 = разрушен`; при `ОБОЛОЧКА · Корабль отделён = да` проверок нет. Период берётся из листа в момент броска и пишется в событие, поэтому снятый позже Кристалл не пересчитывает прошлые проверки. Страница показывает, сколько проверок к броску, трекер в боковой панели — тоже, ссылкой на страницу.

«Бросить проверку» бросает d6 проверки и кубик таблицы вместе: d6 или d12 по уровню партии (переключатель на странице). На 1 встреча состоялась, и сайт бросает её состав по `count`; иначе кубик таблицы показан приглушённо и выпадением не считается. «Бросать до встречи» бросает накопленные проверки по порядку до первой встречи одним событием. «Бросали сами» — ввод d6, кубика таблицы и, если бросали, состава; без встречи кубик таблицы можно не вводить. Выпавшая строка показывает состав с существами, признаки, мотивацию, варианты сцены, другие карточки строки связей и поля листа, которые называет карточка, — теми же панелями `Group`, что «Состояние мира». Гарантированное эхо приходит из очереди «персонаж выбыл» (см. «Вы сами»): пока кто-то ждёт и снимок шести ходов назад есть (`echoOf` из `site/encounters.js`), ближайшая проверка — № 12 без броска, «бросить проверку» называется «гарантированное эхо», а ввод своих кубиков закрыт; над кнопками — кто ждёт и ждёт ли снимка. Прежняя отметка «ждёт гарантированное эхо» осталась только для старых сохранений: кнопка видна, пока отметка стоит, и снимает её. Таблица внизу считает, сколько раз выпадала каждая строка; строки выше уровня партии приглушены.

Всё это — состояние партии, срез `encounters`: `turns` (двигает счётчик), `party-level` `{ level }`, `encounter-outside` `{ outside }`, `encounter-echo` `{ pending }` и `encounter-check` `{ period, level, die, rolls: [{ check, row }], count, entered, echo }` — одна или несколько проверок, каждая тратит `period` шагов; встречей может быть только последняя. Журнал пишет их словами.

## Трекер ходов

Боковая панель на всех страницах — трекер ходов (`site/turns.js`) по [П3, раздел 1](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#1.%20Ход%20исследования): Мастер отмечает ход исследования, когда прошло около 10 минут значимой деятельности. Трекер показывает, сколько прошло ходов и времени, время суток и сколько прошло с последнего долгого отдыха. Кнопки: «+1 ход», «шумный ход», «+1 час» (6 ходов) и «отдых 8 ч» (48 ходов); последняя запись трекера стоит под кнопками с кнопкой «отменить», работает и Ctrl+Z. Когда накопились проверки случайных встреч или ждёт гарантированное эхо, под кнопками — ссылка на страницу встреч с их числом. Ниже — подсказка, когда живая карта расходится с «группа вне Корабля» (`placeHint` из `site/encounters.js`): токен группы и все токены персонажей на карте стоят в комнатах `outside`, а счётчик идёт, или хоть один из них внутри, а счётчик стоит. Подсказка называет токен и комнату, её кнопка шлёт то же `encounter-outside`, что переключатель страницы встреч. Сам счётчик сайт не переключает: токены необязательны, а в 41 важно, вся ли группа там ([П13, 41](../korabl_vremeni_punkt_13_room_by_room_pf2_overlay.md#41.%20Ферма%2054%20года%20назад)). Токен вне карты не считается.

Всё это — состояние партии, срез `turns`:

- событие `turns` `{ count, noisy, rest }` — прошло `count` ходов. Шумный ход ([П3, раздел 9](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#9.%20Шум)) — один ход с `noisy: true`: по нему счётчик случайных встреч (`site/encounters.js`) сдвигается ещё на 1. `rest: true` — долгий отдых: по решению в [П3, раздел 4](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#4.%20Типовые%20действия%20и%20стоимость%20времени) это 48 обычных ходов со счётчиком встреч, и отсчёт «с отдыха» начинается заново;
- событие `clock-set` `{ start, at }` — время суток. Часа прихода в каноне нет, его задаёт Мастер, вводя время «сейчас»; хранится время на ходу 0 в минутах от полуночи дня 1 (дня прихода партии), поэтому каждый следующий ход сдвигает часы. `at` — введённое время, для журнала; `start: null` снимает время суток. Новое время меняет только часы и минуты: день остаётся тем же.

Поле времени сохраняется, когда уходишь из него или жмёшь Enter; Escape возвращает прежнее.

## Сцена

Страница «Игра → Сцена» (`site/pages/scene.js`, состояние — `site/scene.js`) ведёт один бой: кто в нём, порядок инициативы, у каждого экземпляра свои ПЗ и состояния. Числа (КБ, ПЗ, спасброски, модификатор инициативы) берутся из карточки канона; экземпляры — состояние партии. Существо или опасность добавляются полем с подсказками на странице (можно сразу несколько), кнопкой «В сцену» на карточке существа или опасности, кнопкой «в сцену» у них же в карточках страницы комнаты (каждый щелчок — ещё один экземпляр) и кнопкой «в сцену» у состава выпавшей случайной встречи (по одному экземпляру каждого). Персонажи партии добавляются кнопками «Партия: …» и «вся партия» на странице и кнопкой «в сцену» на «Вы сами»; в сцене у персонажа КБ и спасброски из импорта, а ПЗ и состояния — те же, что на «Вы сами»: строка шлёт события партии (`pc-hp`, `pc-condition`), своей копии сцена не держит. Инициативу игроки бросают сами: у персонажа нет модификатора, «Бросить инициативу» его пропускает, результат Мастер вписывает в поле. Кто угодно другой без карточки добавляется по имени — только для порядка инициативы. Второй экземпляр того же имени нумеруется: «Пёс», «Пёс 2»; персонаж имя не меняет.

«Бросить инициативу» бросает d20 + Восприятие (у опасности — Скрытность) всем, у кого инициативы ещё нет, одним событием; поле инициативы можно заполнить и руками. Порядок — по убыванию инициативы, при равенстве и без инициативы — в порядке добавления. «Начать бой» / «Следующий ход» двигают отметку хода и счётчик раундов; кнопка отправляет тот ход, который видит, поэтому двойной клик не пропускает участника. Урон и лечение держат ПЗ между 0 и максимумом, участник на 0 ПЗ приглушён. Состояния — из словаря, с подсказкой при наведении; у состояния со значением — кнопки «−» и «+», повторный выбор его в списке тоже добавляет 1.

Срез `scene`, события (в каждом — имена, которые пишет журнал):

- `scene-add` `{ list: [{ kind, ref, name, max, mod }] }` — `kind`: `creature`, `hazard`, `pc` (персонаж партии, `ref` — его id, `max` и `mod` — `null`) или `other`; экземпляр получает id `<seq>.<n>`; журнал пишет одинаковые имена один раз с числом: «вошли Хрустальный Паук ×3»;
- `scene-hp` `{ id, name, delta }`, `scene-init` `{ list: [{ id, name, value }] }`;
- `scene-condition` `{ id, name, condition, value }` — имя состояния без « N»; `value` — число, `true` для состояния без значения, `null` снимает;
- `scene-remove` `{ id, name }` — если убран тот, чей ход, отметка переходит к предыдущему, и раунд продолжается;
- `scene-turn` `{ id, name, round }`, `scene-clear` `{}` — «Завершить сцену» очищает её (отменяется, как любое действие).

## Карта

Граф карты сборщик берёт из [`karta_graf.json`](../karta_graf.json) — его сняли с бумажной карты трассировщиком `tools/karta_trace.html` (см. [карту Корабля, 4.1](../karta_korablya.md#4.1.%20Граф%20карты)); разбор — `tools/site_map.py`. Сам граф сборщик не меняет, только проверяет и готовит к рисованию. В `canon.json` это `map`:

- `doc`, `key` — раздел сайта, чей текст ссылается на `karta_graf.json` (сейчас «4.1. Граф карты»); найден по ссылке, а не по заголовку;
- `box` — `[x, y, ширина, высота]`: рамка всех точек с полями 60, в координатах трассировщика;
- `types` — типы переходов в порядке файла: `id`, `title` (как в файле), `count`;
- `nodes` — комнаты (точки с `room`): `id`, `x`, `y`, `room`. Остальные точки — изгибы коридоров, они нужны только как концы переходов. Пометки трассировки на точках и переходах сборщик не отдаёт: они писались для проверки оцифровки, а не для игры;
- `edges` — переходы: `id` (по нему живая карта находит Мерцающие стены и правки), `type`, точки концов `a`, `b`, их координаты `x1`, `y1`, `x2`, `y2`. Каждая точка графа — конец какого-то перехода, поэтому новый проход цепляется к точкам, найденным среди концов;
- `points` — сколько всего точек в файле;
- `start` — комната, где группа начинает (комната П13 со `start`);
- `photo` — фото бумажной карты, с которого снят граф: `src` (копия в `site/data/`), `file` (исходный файл), `width` и `height` файла и `transform` — матрица SVG, которая поворачивает фото на `image.rotation` графа и масштабирует его в кадр графа. Фото то же, что у `tools/karta_analyze.py` (константа `PHOTO`), поэтому наложение из скрипта и подложка сайта совпадают. Сервер отдаёт только `site/`, поэтому сборщик при каждой записи данных кладёт копию фото в `site/data/karta_foto.jpg` — в git она не хранится, как и `canon.json`. Из копии вырезан блок EXIF: у фото есть метка ориентации, браузер повернул бы по ней фото сам, а матрица, как и `karta_analyze.py`, рассчитана на пиксели без поворота. Без фото — `null`.

Файла нет, он не читается или формат не `karta-trace/1` — ошибка, и `map` = `null`. Повтор `id` точки или перехода, переход в несуществующую точку и переход неизвестного типа (переход пропускается), номер комнаты, которой нет в П13, стартовая комната группы или НПС без точки на карте — ошибки; комната П13 без точки, граф, на который не ссылается ни один раздел, фото, которого нет или которое не читается как JPEG, и фото, чьи пропорции не сходятся с кадром графа, — предупреждения. Отчёт сборщика считает `map`: `{ nodes, edges }`.

**Страница «Игра → Карта»** (`site/pages/map.js`). `#/game/map` — граф целиком, `#/game/map/<номер>` — то же с подсвеченной комнатой; номера, которого нет на карте, страница так и говорит. Граф вписан в экран под шапкой целиком, без масштаба и прокрутки: высотой в экран, шириной сколько позволяет пропорция рамки графа (`--map-ratio`). Справа — колонка «особых» переходов со своей прокруткой: Мерцающие стены, потайные двери, запертые и особые переходы. У каждого перехода в колонке номер и комнаты по обе стороны («№ 643 16 — 4»): точка на конце стены — обычно изгиб коридора, поэтому комната находится обходом по коридорам и дверям (`sidesOf` в `site/pages/map_edit_panel.js`; им же подписаны переходы в подсказках и правках). Щелчок по номеру ставит на переход ореол на карте, повторный снимает; пока указатель над строкой колонки, ореол у перехода тоже есть.

**Попап перехода.** Щелчок по Мерцающей стене, потайной двери, запертому или особому переходу на карте выбирает его в колонке и открывает попап у точки щелчка: подпись перехода и то же, что в его строке, — состояние стены и её кнопки, отметка «найдена» у потайной двери; у запертых и особых своего состояния нет, и попап только называет их. Попап стоит справа и ниже точки, если помещается, иначе слева или выше, и всегда внутри рамки карты: его размер меряется после каждой отрисовки, потому что ширина зависит от показанного состояния (`place` в `site/pages/map.js`). Закрывают попап крестик, Escape, щелчок по карте мимо переходов, повторный щелчок по тому же переходу и режим правки или переноса токена. Если странице не хватает ширины, чтобы оставить карте ~700px, колонка уходит под карту (container query по ширине страницы). Комнаты — кружки с номером, щелчок ведёт на страницу комнаты, в подсказке — номер и название из П13. Линии — переходы. Каждый тип перехода — слой с флажком, цветом и числом; цвета — переменные `--edge-<тип>` в `style.css`. При открытии страницы скрыты коридоры и открытые проходы (это 276 из 333 линий, а фото карты их и так показывает), потайные двери и особые переходы. Переход скрытого слоя всё равно виден, пока у него ореол: выбран или под указателем в колонке. Открыть карту можно из навигации «Игры», ссылкой «Карта Корабля» в боковой панели и ссылкой «На карте» на странице комнаты. Слои, фото, легенда, токены и правка карты — под картой. Под графом лежит фото бумажной карты (`map.photo`) в полную яркость; у него свой флажок «Фото карты» (включён) и ползунок, которым фото можно приглушить. Слои, фото и выбранный переход — вид страницы, а не состояние партии: в журнал они не пишутся.

**Мерцающие стены** ([П5, раздел 6](../korabl_vremeni_punkt_5_fundamentalnye_sistemy.md#6.%20Мерцающие%20Стены)). Стены — переходы графа с типом `flicker`, стена называется `id` своего перехода («№ 643»). Состояние ведёт `site/walls.js` (срез `walls`), панель в колонке рядом с картой — `site/pages/map.js`. У стены три состояния: существует, отсутствует, не определена (ещё ни разу не бросалась). Бросок ленивый, как в П5, 6.2: ход трекера не бросает сам, а помечает «нужен бросок» каждую известную стену, которая не на виду. Бросить стену можно из её строки или всем нужным сразу одним событием. Стена на виду держит состояние, сколько бы ходов ни прошло: видит ли её группа, решает Мастер, поэтому отметка «на виду» стоит, пока её не снимут. Состояние можно задать руками — бросок настоящим кубиком или занятый объём, где стена не появляется (П5, 6.6). Поле листа `ХРУСТАЛЬ · Мерцающие Стены стабилизированы` стоит на панели той же кнопкой, что на «Состоянии мира»: при «да» ходы стены не трогают, стена с известным состоянием держит его навсегда, а неопределённая или ждущая броска бросается ещё раз, и это её состояние навсегда (П5, 6.10). В строке колонки состояние словами не пишется: это подсвеченная кнопка «существует» или «отсутствует», у ждущей броска — бледная, с пунктирной рамкой, и тогда выделена «бросить»; у неопределённой не подсвечена ни одна. Попап на карте называет состояние и словами. Щелчок с Shift по стене на карте или по её номеру в колонке добавляет стену к выбранным или убирает её; пока выбрано больше одной, вверху колонки под блоком правки стоит «Выбрано стен: N» с кнопками «на виду», «не на виду» (одно событие `wall-seen` на все), «бросить нужные» (одно `wall-roll`) и «снять выбор». Выбор снимают и Escape без открытого попапа, и щелчок по карте мимо переходов. На карте существующая стена — сплошная линия, отсутствующая — пунктир, неопределённая — серые точки, ждущая броска — бледная, стена на виду — с ореолом. Все стены перечислены в колонке. Щелчок по стене на карте выбирает её: строка подсвечивается и прокручивается в колонке; щелчок по номеру в колонке показывает стену на карте. Ссылка «Правила» ведёт в родительский раздел источника поля (П5, 6.8 → П5, 6), ключа раздела в коде страницы нет.

События:

- `wall-roll` `{ list: [{ id, exists }] }` — броски 50% сайта, одной стены или нескольких сразу;
- `wall-set` `{ id, exists }` — состояние, заданное Мастером;
- `wall-seen` `{ list: [id], seen }` — стены на виду у группы или больше не на виду;
- срез слушает и чужие события: `turns` — граница хода, `world-set` поля стабилизации. Лист начинается с «нет», поэтому снятое изменение (`value: null`) — тоже «нет».

**Потайные двери** ([П3, раздел 5](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#5.%20Поиск%20и%20скрытые%20проходы)). Переходы графа с типом `secret`, их два: 20 — 21 и 2 — 38. Нашла ли группа дверь — отметка Мастера «найдена» в колонке, как «на виду» у стены; поля листа П2 для неё нет, это состояние партии. Состояние ведёт `site/secrets.js` (срез `secrets`). На карте ненайденная дверь — пунктир, найденная — сплошная линия, в подсказке — её состояние.

События:

- `secret-found` `{ id, found, label }` — дверь найдена или отметка снята; `label` — подпись перехода для журнала.

**Запертые и особые переходы** (`locked`, `special`) стоят в колонке списком без своего состояния: номер, комнаты, тип.

**Правка карты** ([П5, 4.6 и 4.11](../korabl_vremeni_punkt_5_fundamentalnye_sistemy.md#4.11.%20Карта)). Прямые изменения мира: их делают Браслет, результат 6 пульта Зала управления или обычные инструменты. Это не смена фазы, поэтому правка действует и на виду у группы, и поверх стабилизации стен (П5, 6.1 и 6.11). Сама она не откатывается. Состояние ведёт `site/map_edits.js` (срез `mapEdits`), правка карты — `site/pages/map_edit_panel.js`: вверху колонки рядом с картой — блок «Правка карты» с тремя режимами (`EditBar`, он остаётся наверху, пока колонка прокручивается), в конце колонки — «Правки карты», список сделанных (`EditList`). Правок три вида:

- «Мерцающая стена убрана навсегда» — стена больше не мерцает и не бросается, проход открыт. На карте — бледная серая линия, в панели стен — «убрана навсегда»;
- «Переход закрыт» — поверх перехода зарос хрусталь: переход бледнеет, на середине — крест;
- «Новый проход» — два щелчка по карте. Конец цепляется к ближайшей точке графа не дальше 40 единиц, иначе встаёт там, где щёлкнули, в глухом хрустале. На карте — пунктир своего цвета (`--edge-new`), он виден при любых слоях.

Пока выбран режим правки, щелчок по карте выбирает цель, а не открывает комнату; подходящие цели подсвечиваются. Режим с целью включается и из попапа перехода: у Мерцающей стены — «убрать навсегда…», у потайной двери, запертого и особого перехода — «закрыть переход…»; причину, заметку и «Применить» даёт блок колонки. «Отмена» выключает режим. У правки есть причина — Браслет, пульт (только для Мерцающей стены) или иное — и необязательная заметка. «Снять» возвращает граф в этом месте к исходному виду; убранная и возвращённая стена получает то состояние, которое у неё было.

Карта — запись этих правок. Поле листа `ХРУСТАЛЬ · Изменённые стены/двери` остаётся для того, чего граф не покажет: наросты, форма комнат. «Состояние мира» перечисляет правки карты под этим полем со ссылкой на карту.

Первое структурное применение Браслета выставляет `ХРУСТАЛЬ · Браслет уже активирован` и `ХРУСТАЛЬ · Мерцающие Стены стабилизированы` (триггер П13, комната 11, по П5, 6.8). Правка с причиной «Браслет» при поле «активирован» не «да» отправляет следом два события `world-set`. Каждое отменяется отдельно, а поле, которое уже стоит «да», не трогается.

События (в каждом — слова, которые пишет журнал):

- `map-edit` `{ kind, cause, label, note? }` и по виду: `wall-gone` и `closed` — `{ edge }`, `passage` — `{ x1, y1, x2, y2, a, b }`, где `a`, `b` — точки графа или `null` для глухого хрусталя. `id` правки — номер события. Вторая правка того же перехода не записывается: это двойной щелчок;
- `map-edit-drop` `{ id, label }` — правка снята.

**Токены.** Где стоят группа и НПС — с точностью до комнаты. Состояние ведёт `site/tokens.js` (срез `tokens`), панель «Токены» — `site/pages/map_token_panel.js`. Токены канона:

- «Группа» стоит в стартовой комнате (`map.start`, комната 1);
- каждый НПС карточек П8, у которого в поле «Старт» номер комнаты, стоит там (`npc.start`: Сарежейн — 19, Кузина — 24, Пёс — 32). Остальные НПС (Корабль Времени, Леди, Хозяин и другие) в списке не стоят: Мастер ставит их списком «Поставить НПС…» панели — НПС встаёт в комнату группы и дальше остаётся в списке, даже если уйдёт с карты (`offMapNpcs` в `site/tokens.js`).

Мастер добавляет токены по имени: персонаж, если группа разделилась, или кто угодно ещё; такой токен появляется в комнате группы. На карте токен — значок с инициалами под комнатой, цвет — по виду (группа и персонажи, НПС, прочее), имя в подсказке, и подсказка комнаты перечисляет, кто в ней. Щелчок по значку — на карте или в панели — выбирает токен, следующий щелчок по комнате переносит его туда; повторный щелчок по значку снимает выбор. В панели у каждого токена есть и список комнат. У токена канона есть кнопка «исходное», добавленный токен удаляется. Перенос — режим той же карты, что и правки: выбор токена выключает вид правки, и наоборот.

События (в каждом — имя для журнала):

- `token-move` `{ id, name, room }` — `room: null` убирает токен с карты. `id`: `party`, `npc:<id НПС>` или номер события, добавившего токен;
- `token-add` `{ name, kind, room }` — `kind`: `character` или `other`;
- `token-remove` `{ id, name }` — добавленный токен удалён; токен канона только уходит с карты.

## Вехи

Каталог вех и пороги повышения уровня сборщик берёт из [П14](../korabl_vremeni_punkt_14_progression_i_temp.md); разбор — `tools/site_milestones.py`. Разделы он находит по названию, номера в коде нет. В `canon.json` это `milestones`:

- `doc`; ключи разделов, на которые ссылается страница: `catalog` (4), `scheme` (3.4), `readiness` (3.5), `package` (3.7, правило причинного пакета), `paths` (5.2), `fallback` (5.3), `procedure` (14);
- `categories` — `[{name, measures}]` из таблицы [3.2](../korabl_vremeni_punkt_14_progression_i_temp.md#3.2.%20Категории); `scales` — ярлыки масштаба из списка [3.3](../korabl_vremeni_punkt_14_progression_i_temp.md#3.3.%20Масштаб%20условия), от слабого к сильному;
- `levels` — `{from, to}` из заголовка «3 → 4» под 3.4; оба уровня должны быть в таблице уровней случайных встреч;
- `knowledge` — категория, которая только знание, из правила «Только знание — условия категории «…»» в 3.4 ([реестр, тема 1.16](../otkrytye_voprosy.md#1.16.%20Какие%20вехи%20—%20только%20знание));
- `fallback_rule` — `{conditions, categories, strong}` из жирного правила 5.3 «**3 условия, минимум 2 категории, хотя бы одно стратегическое или крупное**»; `strong` — масштабы, которые правило называет;
- `crash` — `id` вехи, которую требует основной порог: разбор берёт её из слов «засчитана веха «…»» в 5.2;
- `readiness_items` — три условия готовности к развязке, нумерованный список 3.5, markdown;
- `paths_items` — `[{id, name, claim, step}]`, строки таблицы 5.2: путь, как звучит заявка, когда засчитан первый необратимый шаг;
- `items` — 23 условия каталога, разделы «Название: условие» в разделе 4: `id` (латиницей из названия), `name`, `goal`, `key`, `category`, `scale`, `once` — строки «**Категория:**», «**Масштаб:**», «**Однократность:**» без точки.

Каталог сверяется с итоговой таблицей [раздела 15](../korabl_vremeni_punkt_14_progression_i_temp.md#15.%20Итоговая%20таблица%20условий%20вех) — те же названия, категории и масштабы — и с названиями карты опорных правил 3.8. Нет раздела, категория или масштаб не из 3.2 и 3.3, расхождение с таблицей, строка таблицы не из своего числа столбцов, правило, которое не читается, и уровень не из таблицы встреч — ошибки сборщика. Разделы П14 вне карточек вех попадают в список «не показаны на карточках» отчёта сборщика.

**Страница «Игра → Вехи»** (`site/pages/milestones.js`, состояние и пороги — `site/milestones.js`). Сверху — уровень партии и оба порога 3 → 4 с разбором по пунктам: основной — засчитана веха `crash`, и хотя бы один путь заявлен и по нему сделан первый шаг; запасной — число условий и категорий против `fallback_rule` и хотя бы одно условие масштаба из `strong` не из категории `knowledge`. Когда порог выполнен, страница пишет «готово и ожидает применения» и даёт кнопку «применить повышение»: она шлёт `party-level` `{ level: 4 }` — то же событие, что переключатель уровня на странице встреч. Отдельного состояния повышения нет: «применено» значит, что уровень партии уже 4, поэтому страницы не расходятся. Ниже — таблица путей 5.2 с отметками «заявлен» и «шаг сделан» у каждого (пути не исключают друг друга), реестр развития — полученные вехи по порядку с уровнем получения, заметкой о состоянии мира и кнопкой «снять», — три условия готовности к развязке и каталог по категориям с поиском. Условие каталога раскрывается: его текст из П14, однократность, ссылка на правило причинного пакета и поле «что теперь истинно в мире» с кнопкой «отметить». Все отметки ставит Мастер: лист П2 не хранит, прозвучала ли заявка за столом.

Всё это — состояние партии, срез `milestones`:

- `milestone-mark` `{ id, name, level, note }` — условие получено на уровне партии этого момента; `note` — коротко, что теперь истинно в мире (реестр развития, [П14, 14](../korabl_vremeni_punkt_14_progression_i_temp.md#14.%20Краткая%20Мастер-процедура%20повышения%20уровня), шаг 3). Второй раз то же условие не отмечается;
- `milestone-drop` `{ id, name }` — отметка была ошибкой;
- `milestone-path` `{ id, name, what, on }` — `what`: `claimed` (путь заявлен) или `made` (сделан первый необратимый шаг);
- `milestone-ready` `{ index, on }` — условие готовности к развязке по номеру.

## Импорт из Pathbuilder

Персонажи партии — состояние партии, а не канон: игроки присылают экспорт Pathbuilder 2e перед первой игрой и после повышения до 4-го уровня ([книга игрока](../kniga_igroka.md)), и экспорт попадает в журнал событием. Срез `party` и разбор экспорта — `site/party.js`, страница — «Инструменты → Импорт из Pathbuilder» (`site/pages/pathbuilder.js`).

- **Разбор** (`fromPathbuilder`) берёт из `build` экспорта имя, класс, уровень, родословную, наследие, предысторию, размер, скорость; ячейки заклинаний из `spellCasters[].perDay` (рангами от 1-го; заговоры не считаются), очки фокусировки и названия фокусных заклинаний; оружие, доспехи, снаряжение с количеством и деньги. Числа он выводит по базовым правилам: ПЗ = ПЗ родословной + бонус + (ПЗ класса + бонус за уровень + модификатор Телосложения) × уровень; КБ — `acTotal.acTotal`; спасброски и Восприятие — ранг владения + уровень (если обучен) + модификатор. Бонусов предметов, рун и черт (например, Incredible Initiative) экспорт в читаемом виде не даёт, поэтому Мастер сверяет числа перед импортом: `derived` — вычисленное, `numbers` — то, что оставил Мастер; исправленное помечено.
- **Расходники.** Pathbuilder их не отмечает. Отмеченная строка снаряжения становится счётчиком с числом из экспорта; первые отметки нового персонажа — догадка по названию (зелья, свитки, талисманы, боеприпасы и т. п.). Свои счётчики — то, чего в экспорте нет, например временные талисманы тавматурга.
- **Повторный импорт.** Файл персонажа, который уже в партии (по имени), предлагает обновить его: меняются сборка и счётчики, остальное состояние персонажа остаётся — быстрые поля подшага 19c, в том числе полученный урон. Отметки расходников берутся из прежнего импорта. Если уровень персонажа не равен уровню партии, страница это пишет.

События среза `party`:

- `pc-import` `{ id, build, counters }` — `id` `null` — новый персонаж, его `id` — номер события; иначе обновление; `counters` — `[{ name, max }]`;
- `pc-remove` `{ id, name }` — ошибочный импорт. Выбывший персонаж не удаляется: это «персонаж выбыл» подшага 19f.

Журнал пишет их словами.

## «Вы сами»

Страница «Игра → Вы сами» (`site/pages/yourselves.js`) — быстрые поля партии: из них восстанавливается эхо встречи «Вы сами» ([П6, 9.4](../korabl_vremeni_punkt_6_temporal_paradox.md#9.4.%20Восстановление%20состояния%206%20ходов%20назад)). У каждого персонажа — КБ, спасброски и Восприятие из импорта, ПЗ с полем урона и лечения и временные ПЗ, состояния из словаря, ячейки заклинаний по рангам и очки фокусировки («осталось N из M», −1 и +1), кнопка «ежедневная подготовка», счётчики расходников и заметка — что при себе и что известно. Персонаж с 0 ПЗ помечен; состояния «без сознания» и «умирает» Мастер ставит сам. Поля ПЗ и состояний — те же компоненты, что в сцене (`HitPoints`, `Conditions` из `site/pages/scene.js`), с обработчиками вместо событий сцены.

Быстрое состояние хранится рядом со сборкой, в срезе `party` (`site/party.js`): `damage` — полученный урон, а не текущие ПЗ, `temp`, `spent` — потраченное по ключам `slot|<класс>|<ранг>`, `focus`, `counter|<название>`, а не оставшееся, `conditions`, `note`. Поэтому новая сборка при повторном импорте их сохраняет: персонаж с уроном 37 после импорта 4-го уровня с 46 ПЗ имеет 9. События:

- `pc-hp` `{ id, name, delta }` — урон (отрицательный) снимает сначала временные ПЗ; ПЗ остаются между 0 и максимумом;
- `pc-temp` `{ id, name, value }` — временные ПЗ, 0 снимает их;
- `pc-spend` `{ id, name, what, key, label, delta }` — потрачено (`delta` > 0) или возвращено; `what` — `slot`, `focus` или `counter`; `label` — как это называет журнал; потраченное держится между 0 и пределом;
- `pc-condition` `{ id, name, condition, value }` — как `scene-condition`;
- `pc-note` `{ id, name, text }` — `null` убирает заметку;
- `pc-prepare` `{ id, name }` — ежедневная подготовка: ячейки и фокус возвращаются, ПЗ и счётчики — нет, их Мастер ставит сам.

**Снимки** — не события: срез `party` сам считает ходы трекера (`turns`) и, когда счётчик доходит до хода k, копирует партию как снимок хода k — состояние на начало этого хода. Хранятся ходы с N − 6 по N, где N — ход сейчас: страница показывает шесть до него, снимок начала этого хода нужен «персонаж выбыл» подшага 19f. Снимок хода 0 берётся на первом ходу трекера: до него партию только импортируют. Отмена и загрузка сохранения пересобирают снимки, как любое состояние, а ошибочный импорт (`pc-remove`) исчезает и из них. Раздел «Снимки» страницы — кнопки «−1» … «−6», таблица снимка (ПЗ, состояния, ячейки и фокус, расходники, заметка) и выделение ячеек, которые отличаются от нынешнего состояния; при наведении — как сейчас.

**Случайная встреча № 12.** Когда проверка выпадает на № 12 не гарантированным эхом, срез запоминает с ней снимок шестью ходами раньше (`echo12`: `{ check, from, list, rolls }`), и следующие ходы его не вытесняют. Под карточкой встречи страница встреч показывает этот снимок и кнопку d8 на каждого ([П6, 9.5](../korabl_vremeni_punkt_6_temporal_paradox.md#9.5.%20Изменение%20состава)): при 1 персонаж погиб в ветке, погибли все — несостоявшийся отголосок; снимка нет — тоже ([П6, 9.3](../korabl_vremeni_punkt_6_temporal_paradox.md#9.3.%20Какая%20версия%20используется)). Наёмники и спутники без листа бросаются за столом. Событие — `echo-d8` `{ check, rolls: [{ id, name, roll }] }`.

**Гарантированное эхо** ([П6, 10.8](../korabl_vremeni_punkt_6_temporal_paradox.md#10.8.%20Гарантированное%20эхо), [реестр, тема 1.17](../otkrytye_voprosy.md#1.17.%20Когда%20гарантированное%20эхо%20не%20может%20прийти%20на%20ближайшей%20проверке)). Кнопка «персонаж выбыл» на карточке спрашивает причину из «Условия» 10.8 и ставит персонажа в очередь; он остаётся в партии пометкой «выбыл», его карточка говорит, ждёт ли он и чего, и даёт «отменить выбывание». Пока снимка шести ходов назад нет, проверки идут как обычно; потом каждая проверка приносит одно эхо, в порядке выбывания. Эхо берётся из снимка шестью ходами раньше проверки, но не позже хода выбывания; снимок хода выбывания очередь хранит сама, потому что кольцо снимков его может уже вытеснить. Под проверкой страница встреч показывает выжившего со штрафом — половина максимума ПЗ с округлением вниз и «ранен» не меньше 1, остальное как в снимке, — напоминание о памяти, привязке и дублях с тела и кнопку «эхо присоединилось». Вернувшийся носит пометку «эхо Корабля» с кнопкой «закрепить»: Оболочка с управлением снимает привязку к хрустальным стенам ([П8, 9.6](../korabl_vremeni_punkt_8_fraktsii_i_npc.md#9.6.%20После%20получения%20управления)). События:

- `pc-out` `{ id, name, reason }` — выбыл; в очередь (`queue`: `[{ id, name, turn, seq, atDrop }]`);
- `encounter-check` с `echo: true` снимает голову очереди в `arrived`: `{ check, id, name, from, pc, joined }`; очередь пуста — `{ check, id: null }`;
- `pc-echo-join` `{ check, id, name }` — персонаж получает состояние эха, `out` снимается, `echo` — `{ anchored: false }`;
- `pc-echo-anchor` `{ id, name, anchored }`.

## Временные дубли

Страница «Игра → Временные дубли» (`site/pages/doubles.js`) — реестр предметов, у которых есть версии из разных времён ([П6, 6](../korabl_vremeni_punkt_6_temporal_paradox.md#6.%20Временные%20дубли%20предметов)). Только предметы, как раздел 6 П6 и поле «Временные дубли» листа П2: версии персонажей ведёт «Вы сами». Мастер заводит объект — название и, если это предмет канона, ссылку на карточку П12 — и его версии с полями [П6, 6.7](../korabl_vremeni_punkt_6_temporal_paradox.md#6.7.%20Отслеживание%20происхождения): эпоха, личный порядок на мировой линии (1 — самая ранняя; равные числа — версии, которые не упорядочить, [7.9](../korabl_vremeni_punkt_6_temporal_paradox.md#7.9.%20Какой%20экземпляр%20остаётся)), как попала в это время, у кого из партии и где, отметки «в закрытом непрозрачном контейнере» ([6.6](../korabl_vremeni_punkt_6_temporal_paradox.md#6.6.%20Закрытые%20контейнеры)), «временной остаток» и «вещь эха» ([9.8](../korabl_vremeni_punkt_6_temporal_paradox.md#9.8.%20Обмен%20предметами)). Объект — «Объект-N», версия — «В-N», как в записи [15.5](../korabl_vremeni_punkt_6_temporal_paradox.md#15.5.%20Предметы).

Пары не хранятся: страница выводит их из живых версий объекта в порядке [темы 1.18](../otkrytye_voprosy.md#1.18.%20Три%20детали%20коллапса%20временных%20дублей) — самая ранняя с каждой следующей, затем вторая с каждой следующей. Версия, которая ушла («исчезла», «уничтожена», «история переписала»), остаётся в таблице пометкой с ходом и без пар; «вернуть» — отмена этой записи. Новая версия даёт новые пары ([7.6](../korabl_vremeni_punkt_6_temporal_paradox.md#7.6.%20Когда%20возможна%20новая%20проверка%20коллапса)). Персонаж, удалённый из партии, остаётся носителем под своим именем с пометкой «нет в партии».

«Совместно наблюдались» — у пары или у объекта, когда вместе видны несколько версий ([П6, 7](../korabl_vremeni_punkt_6_temporal_paradox.md#7.%20Процедура%20коллапса%20временных%20дублей)). Мастер отмечает, какие версии видны; версия в закрытом контейнере не участвует. Непроверенные пары идут по одной в порядке темы 1.18: «бросить d100», «бросить до конца» или «бросали сами» с вводом d100; 1–50 — коллапс. У каждой пары своё событие, поэтому отмена и журнал — попарные. «Устойчиво» остаётся за парой навсегда, даже если версия уходила и вернулась; новая версия даёт новую непроверенную пару ([7.6](../korabl_vremeni_punkt_6_temporal_paradox.md#7.6.%20Когда%20возможна%20новая%20проверка%20коллапса)). При коллапсе остаётся более поздняя по личному порядку версия, при равном порядке — 50/50 сайта или выбор Мастера после броска за столом ([7.9](../korabl_vremeni_punkt_6_temporal_paradox.md#7.9.%20Какой%20экземпляр%20остаётся)); исчезнувшая версия уходит с причиной «коллапс», её пары снимаются без броска, выжившая продолжает. «Проверки коллапса» под объектом хранят все проверки ([7.10](../korabl_vremeni_punkt_6_temporal_paradox.md#7.10.%20После%20коллапса)); у коллапса — центр разряда (место выжившей в момент коллапса), карточка «Разряда коллапса временных дублей» П7 и «В сцену».

Реестр виден и на других страницах. Под полем «Временные дубли» листа П2 — на «Состоянии мира» и на страницах комнат 39 и 41 — сводка: у каждого объекта живые версии с местом, пары (устойчивых и непроверенных), коллапсы, и строка о +1 Культа; сама запись поля остаётся для того, что там писали старые сохранения. Карточка встречи № 10 «Служители Парадокса» показывает, есть ли +1 к первому неопределённому броску реакции ([П8, 10.4](../korabl_vremeni_punkt_8_fraktsii_i_npc.md#10.4.%20Отношение%20к%20путешественники%20во%20времени%20и%20дублям)): его даёт пара, проверенная с результатом «устойчиво», обе версии которой существуют, а одну несёт персонаж партии, который не выбыл (`cultPairs`). У прибывшего гарантированного эха — напоминание завести вещи эха в реестре с отметкой «вещь эха» ([П6, 9.8](../korabl_vremeni_punkt_6_temporal_paradox.md#9.8.%20Обмен%20предметами)).

Срез `doubles` (`site/doubles.js`): `{ objects, count }`, у объекта — `{ id, number, name, item, note, versions, count, checks }`, у версии — поля ниже, `id`, `number` и `gone`: `null` или `{ reason, turn, seq }`, у ушедшей в коллапсе ещё `into` — метка выжившей. Проверка в `checks` — поля события `double-check` с `key` пары и `seq`. События:

- `double-object` `{ id, number, name, item, note, changed }` — новый объект (`id: null`, его `id` — номер события) или новые поля; `item` — `id` предмета `canon.items` или `null`; `changed` — названия изменённых полей для журнала;
- `double-object-remove` `{ id, number, name }` — объект заведён по ошибке;
- `double-version` `{ object, id, number, name, label, fields, changed }` — новая версия (`id: null`) или новые поля; `fields` — `era`, `order`, `origin`, `carrier` (`{ id, name }` персонажа или `null`), `where`, `hidden`, `residue`, `echo`;
- `double-version-gone` `{ object, id, number, name, label, reason, turn }` — версия ушла на этом ходу трекера;
- `double-version-remove` `{ object, id, number, name, label }` — версия заведена по ошибке;
- `double-check` `{ object, number, name, a, b, pair, roll, entered, result, survivor, vanished, tie, at, turn }` — проверка коллапса пары версий `a` и `b` (`pair` — «В1 ↔ В2»): `roll` — d100, `entered` — введён Мастером; `result` — `"stable"` или `"collapse"`; при коллапсе `survivor` и `vanished` — `{ id, label }`, `tie` — `null` или `{ entered }`, если порядок равный, `at` — место выжившей, центр разряда; иначе они `null`.

## Журнал

Страница «Игра → Журнал» (`site/pages/journal.js`) — все события сохранения словами, новые сверху: номер записи, ход исследования, к которому она пришла (сумма действующих событий `turns` до неё), время и что сделано. Слова даёт `describe`: у каждого среза своя функция вида `sceneText`, а новый вид событий добавляется туда же. Отменённая запись остаётся зачёркнутой; строка отмены называет, что отменила или вернула.

- **Поиск** — по словам записи, её номеру и комментарию, без учёта регистра и «ё»; все слова запроса должны найтись. Флажки: «отменённые и отмены» (снят — только действующие записи) и «только с комментарием». Показываются первые 100 найденных, дальше — «Показать ещё».
- **Отмена с экрана.** «Отменить» у действующей записи, «вернуть» у отменённой — отмена той отмены, которая её сняла. У строк-отмен своих кнопок нет. «Отменить» и «Вернуть» над списком — то же, что Ctrl+Z и Ctrl+Shift+Z.
- **Заметки и комментарии.** Заметка Мастера — своя строка журнала. Комментарий принадлежит строке и стоит под ней: «комментарий», «изменить», «убрать»; Enter сохраняет, Escape оставляет как было. Правка комментария — событие, её отменяет Ctrl+Z, но отдельной строкой она не показывается, поэтому число строк меньше числа записей в шапке, и страница говорит на сколько.

События: `note` `{ text }` (срез `notes`) и `journal-comment` `{ target, text }` (срез `comments`: номер записи → текст; действует последний, `text: null` убирает комментарий). Страница «Инструменты → Сохранения» показывает только сохранение и файлы.

## Картинки

Картинки — иллюстрации из книги исходника — лежат в `site/img/` и хранятся в git. Картинка попадает в карточку, если имя файла совпадает с id карточки; расширение любое из `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.svg`. Список картинок сайт спрашивает у сервера (`GET /api/images`) при каждом открытии карточки, поэтому новая картинка появляется без перезапуска. Если картинки нет, карточка подсказывает имя файла.

- **Имена.** Существо и НПС — имя латиницей по правилу сборщика («Хрустальный Паук» → `khrustalnyy-pauk`); у НПС с блоком характеристик id тот же, и одна картинка служит обеим карточкам. Опасность и предмет — так же, по названию. Комната — по номеру: `komnata-4`, `komnata-19`, чтобы правка названия не отрывала картинку.
- **Раскладка** (`site/pictures.js`). Файлы обрезаны по-разному, поэтому место картинки выбирается по пропорциям: полоса (высота от 1,8 ширины) — узкой колонкой справа, баннер (ширина от 1,8 высоты) — во всю ширину над описанием, остальные — справа. С картинкой карточка шире на её колонку (до 1120 px): блок и текст идут рядом с картинкой, а ниже неё — на всю ширину; без картинки карточка остаётся шириной для чтения. На узкой карточке (до 720 px) рядом с картинкой нет места, и таблицы проваливались бы под неё, поэтому там любая картинка стоит над текстом высотой до 260 px. На карточке картинка не растягивается больше своего размера. Щелчок открывает её на всё окно; закрывает щелчок или Escape.
- **Схемы в каноне.** Схема к правилу — не карточка, а часть раздела: в markdown канона она пишется картинкой `![Состояния Ока](site/img/oko-sostoyaniya.jpg)`, путь от корня репозитория. Её показывают и Obsidian, и читалка сайта (`site/markdown.js`, путь `site/…` становится адресом на сайте): по центру раздела, высотой до 480 px, щелчок открывает на всё окно. Имя файла — свободное, но не совпадающее с id карточки.
- **«Инструменты → Картинки»** — каждый файл с размером, раскладкой и карточкой или разделом-схемой, к которым он подключён, или пометкой «не подключена»; ниже — карточки без картинки с ожидаемым именем файла. Новый вид карточек добавляется в `pictureOwners` из `site/pictures.js`.

## Как странице хранить состояние

Страница описывает свою часть состояния срезом и меняет его только событиями:

```js
import { defineSlice, dispatch, getState, useStore } from "../store.js";

defineSlice("notes", () => [], {
  note: (notes, data, event) => { notes.push({ seq: event.seq, text: data.text }); },
});

dispatch("note", { text: "Группа спустилась в Подвал" }); // запись уходит на сервер
const notes = useStore(() => getState().notes);          // компонент перерисуется сам
```

Состояние собирается из журнала заново при каждом изменении, поэтому обработчик меняет свежий срез и ничего не помнит между вызовами. Отмена, возврат и синхронизация окон работают для любого среза без дополнительного кода.

# Time Ship Game Master site

A local site that helps the Game Master prepare and run the game. The work plan is [part 3 of the main plan](../time_ship_pf2_master_conversion_plan.md#Часть%203.%20Локальный%20сайт%20для%20Мастера) (in Russian).

## The main rule

The site is a projection of the canon. Rules, creatures, rooms and items are read from sections P1–P14 and the glossary on every start. The only data the site owns is the party's state. If something on the site is wrong, fix the canon, not the site.

## Running

`start.bat` in the repository root. Only Python 3 is required: no npm, no pip. The site opens at `http://127.0.0.1:8741/`.

`start.bat` shows a menu: open the site (starting the server if it is not running), restart, stop. The server runs in the background with no window, so the menu can be closed while the site keeps running. Server output goes to `saves/server.log`. Without the menu: `start.bat open`, `restart`, `stop` or `status`; `--port N` for another port.

## Design

```text
canon (*.md) ──site_build.py──▶ data (JSON, not in git)
                                        │
browser ◀── site_server.py ◀────────────┘
   │  events ▲  SSE
   ▼         │
saves/*.jsonl (event log)
```

- **`tools/site_build.py`** is the builder. It parses the canon markdown into JSON on every server start and reports whatever it could not parse.
- **`tools/site_server.py`** is a server on the Python standard library. It serves `site/`, accepts events, writes them to disk and pushes them to every open window over SSE.
- **State is an event log.** Every action on the site is an event; the state is all events applied in order. Undo is an event too, so nothing is ever erased from the log. A save is a `saves/*.jsonl` file with one event per line.
- **Saves.** The game lives in `saves/current.jsonl`. "New game" and import first move the current file to `saves/archive/`. If the server stopped mid-write, the torn last line is dropped on start and the site warns about it.
- **Frontend**: Preact + htm as a single file in `site/vendor/`, with no build step.
- **Images**: `site/img/<id>.*`. No file means a card without a picture.
- **Links** use Obsidian-style anchors (`file.md#Heading%20text`), as in the canon.

## Canon data

On every start the server runs `tools/site_build.py`, which writes to `site/data/` (not in git):

- **`canon.json`** is the canon for the site. `docs` lists the files in order: P1–P14 and the glossary (`kind: "canon"`), then the companion files the canon links to (`"companion"`): the threat ladder, the map, the open questions register and the discrepancy log. Each file has an `id` (`p1`…`p14`, `slovar_terminov`, …), a full and a short title, and `sections` in order: `key`, `title`, `level`, `number` ("3.4" or `null`), `parent` (the parent's key), `line`, `text` (the section's markdown without its subsections). `links` holds every link between the site files as `[from file, from section, to file, to section]`. `boundaries` holds the canon boundaries: the P1 section "Границы канона" (`doc`, `key`) and `items`, the sections it links to with what the canon leaves open there (`doc`, `key`, `what`). `terms` holds the PF2 terms for the tooltips from glossary section 8: `conditions` (subsection "Состояния") and `traits` ("Признаки"), each with the subsection `key` and `items`: `name`, `en` (the English name or `null`), `text` (what it does, markdown), `href` (an AoN link or `null`) and `own` (a trait of the adventure itself). `creatures` holds the creatures of the P9 and P11 stat blocks (see "Creatures" below), `hazards` the hazards of the P7 blocks (see "Hazards"), `npcs` the NPC cards of P8 (see "NPCs"), `items` the P12 items with knowledge layers (see "Items"), `state` the world state schema from the GM's sheet of P2 (see "World state"), `rooms` the P13 rooms (see "Rooms"), `map` the ship map graph (see "Map").
- **`build_report.json`** is the builder report: a summary per file, the findings and `hidden`, the sections no card shows (see below). The "Tools → Build report" page shows it.

A section key is the Obsidian anchor: the heading text with colons dropped, so a canon link `file.md#anchor` finds its section with no lookup table. Repeated headings ("Тактика" under every NPC) get the keys "Тактика (2)", "Тактика (3)"; as in Obsidian, a link reaches only the first one, and a link to a repeated heading is a warning in the report. A link with no target, or to a file the site does not show, is an error. Source texts and plans (the OCR, the canon completion plan) are not shown on the site, and links to them are not errors.

If the build fails, `canon.json` is removed: the site would rather show no canon than a stale one. To check without writing files: `python tools/site_build.py --check`; two builds in a row must match byte for byte, and the report must have no errors.

**Sections outside the cards.** A card shows only its own sections, so what the canon writes about a creature or an item elsewhere in the same file is seen only in the reader. `tools/site_coverage.py` lists the sections with text in the files that hold the cards (P7, P8, P9, P11, P12; a file a card only folds a section of, such as P5, is not listed) that no card shows: each has `doc`, `key`, `title`, `line`, `top` and `top_title` (its level-2 section, for grouping), `size` (characters of text) and `linked`, true when a card or a page links to it (the body parts of the Dog and the Posthuman in P12, the laws of the world in P7, section 11). Shown means what the pages render: a creature's block and its `info` with everything under them, and the NPC's own text in P11 when the block has no intro; a hazard's and an item's section with everything under it, and their "Подробно" sections (for an item, the "Общие правила" of its section too); an NPC's card in P8 and the sections of its "Подробно" with everything under them. These are not findings but a list to review: most of them are rules and tables. When a page starts showing more or less, `site_coverage.py` changes with it. `python tools/site_build.py --hidden` prints the list.

## Reader

"Канон → Пункты" shows a whole file with its table of contents (level 2–3 headings). A section address is `#/canon/read/<file>/<section key>`, for example `#/canon/read/p8/10.2.%20Организация%20Культа`; without a section it opens the top of the file, without a file it lists the files and the canon boundaries. Canon links lead to the same addresses; links to files outside the site (sources, plans) are dotted and lead nowhere.

- **`site/canon.js`** loads `canon.json` once per window; it also builds section addresses and turns canon links into site addresses, which the cards of later substeps will use too.
- **`site/markdown.js`** turns the canon markdown into HTML, covering exactly what the canon uses (as in Obsidian, a single line break stays a break). To check it, render every section and look for leftover markup: `**`, `](`, table rows.
- **Canon boundaries.** A section the P1 section "Границы канона" links to gets the mark "канон не задаёт: …" with a link to P1. A list line in P1 follows `- what — [link](file.md#section)`; the builder warns about any other. A new boundary is added in P1 only.

## Search

The search box sits in the top bar on every page; Ctrl+K puts the cursor in it. Typing opens "Канон → Поиск" at `#/canon/search/<query>`; further typing replaces that address instead of adding one, so Back leaves the search in one step.

- **`site/search.js`** builds the index in the browser on the first search: the title and the plain text of every section. The canon is about a million characters: the index takes ~60 ms and a query 2–3 ms, so the server takes no part in search.
- A section matches when it holds every word of the query, in the title or the text; a quoted phrase is matched whole. Case and ё/е do not matter, and a word matches inside longer words ("кристалл" → "Кристалла"): there is no morphology, and the prefix stands in for it.
- Order: the canon first, then the companion files (the text of the points rules); then sections with the word in the title; then by hits in the text and by canon order.
- A result shows the section path, the file and the headings above it ("Тактика" repeats for every NPC), a highlighted piece of text at the first hit, and a filter by file.
- A result leads to `#/canon/read/<file>/<key>?q=<query>`: the reader marks the query in that section and scrolls to the first hit. A word cut by markup (half of it bold) is not marked in the reader.

## Term tooltips

PF2 conditions and traits of the glossary are underlined with dots; hovering shows a tooltip with the name, the English name, what the term does, and links to Archives of Nethys and to the glossary. The tooltip stays open while the pointer is on the term or on the tooltip itself, so its links can be clicked. A click on a term pins the tooltip (which is also how it works on a touch screen); a click elsewhere, Escape, scrolling or navigation closes it.

- **`site/terms.js`** marks the terms in the HTML returned by `renderMarkdown`: `<span class="term" data-term="c:3">`, where `c` is a condition, `t` a trait, and the number is the index in `canon.terms`. Any canon text can be marked, so the cards of later substeps only need to call `markTermsHtml`.
- **Conditions** are marked anywhere in the text and in their declined forms, chosen by the ending of the word: the short and full participle ("оглушён", "оглушено", "оглушённый"), the noun ("истощение", "обречённость", "тошноту") and a value after the name ("испуган 1"). "умирает" and "ранен" have their forms spelled out: the general rule misses "умирающий", and "раненых" and "ранение" are plain words. The synonyms of glossary section 2, "усталость" and "продолжительное кровотечение", are marked too.
- **Traits** are marked only in the stat block line "**Признаки:**": as plain words "огонь", "средний" and "животное" are everywhere.
- Nothing is marked inside links, code or italics: spells are italic (*Замедление* is not "замедлен"). The glossary itself is not marked, since the terms are defined there.
- Marking the whole canon takes ~150 ms, spread over the first opening of each file; it finds about 280 terms, and every one of the 45 glossary traits appears in a trait line.

## Creatures

The stat blocks of P9 and P11 are parsed by `tools/site_creatures.py`, which the builder calls. A block lies wholly in one section (`tails_check.py` checks this) and states its level: a heading "… — Существо N", a first line "**Существо N**" or, for the Shell's profile, "**Числовая калибровка:** N-й уровень".

Only what the site cannot read from markdown is parsed; everything else stays markdown and is shown as written. A creature in `canon.json` has:

- `id`: the name in Latin letters ("Хрустальный Паук" → `khrustalnyy-pauk`), also the image file name `site/img/<id>.*`; a repeated `id` is a builder error.
- `doc`, `key`: the block's section; `home`: the section about the creature as a whole. In P11 the block is a subsection of the NPC, and `home` is its parent.
- `name`, `level`, `note` (the remark after the level: "рой"), `budget` (`false` for a profile that does not count as a creature in the encounter budget).
- `traits` from the "**Признаки:**" line; `classification` and `role` from those lines, if present; `aon`, the link to the official block (`title`, `href`), if present.
- `intro`: the description before the block (in P11, the text of `home`); `body`: the block itself without the level, the link and the header lines.
- `numbers` for the combat scene: `perception`, `ac`, `fort`, `ref`, `will`, `hp`; `notes.ac` is a remark on AC ("22, когда броня сломана"). A number that could not be parsed is a warning in the report.
- `abilities`: the block's subsections up to the first "Поведение" or "Изменения"; `info`: the other subsections and, in P11, the NPC's sibling sections ("Тактика", "Переговоры"). When the section above the block has a subsection "Общие правила" (P9, 22.1, the Warehouse prisoners), it comes first in `info` for every block of that section, titled "Общие правила: <section>". Each has `key`, `title` and `actions` ("1 действие", "реакция" or `null`).
- `parts`: the knowledge layers of body parts from P12 (`doc`, `key`, `check`, `layers`, as for an item) or `null`; the Mechanical Dog and the Posthuman have them, see "Items".

**The "Канон → Существа" page** (`site/pages/creatures.js`). `#/canon/creatures` is a table of every creature by point: level, traits, AC, HP, Perception and saves, with a filter by name and trait. The Shell's profile has its level starred: it does not count in the encounter budget. `#/canon/creatures/<id>` is the card: level, traits as tags with tooltips, classification and role, the description, the block in a frame, the abilities with their action count and the folded "Сведения": behaviour, knowledge, remains, and in P11 tactics and negotiation. The Dog and the Posthuman then show "Части тела: слои знаний" with the "знают" marks, as an item card does; a mark is the same `item-layer` event with the creature's `id`. At the bottom are a link to the `home` section in the reader and the official AoN block. In the reader every stat block heading links to its card.

## Hazards

The hazard blocks of P7 are parsed by `tools/site_hazards.py`, which the builder calls, the same way as creatures: only what the site cannot read from markdown is parsed. A block is a section with the level in its heading: "Взрыв часов 41 — Опасность 8", for a complex hazard "… — Опасность 8 (комплексная)". Its reactions and actions are subsections, the last one is "Обоснование". A hazard in `canon.json` has:

- `id`: the name in Latin letters, also the image file name `site/img/<id>.*`; an `id` repeated by another hazard or a creature is a builder error.
- `doc`, `key`: the block's section; `name`, `level`, `complex` (whether the hazard is complex).
- `traits` from the "**Признаки:**" line; `stealth`, the Stealth as written: "+18", "КС 23" or `null` for "—".
- `saves`: the saves of the block's rules in order, without repeats: `save` ("Рефлекс", "Стойкость", "Воля") and `dc`.
- `numbers` for the combat scene, only those the block states: `stealth` (the initiative modifier, when Stealth is written "+N"), `attack`, `ac`, `fort`, `ref`, `hardness`, `hp`, `bt` (Broken Threshold). Only hazards that can be attacked have defenses.
- `body`: the block without its heading and traits line.
- `abilities`: the subsections before "Обоснование" (reactions, routines, "Степени обнаружения"); `info`: "Обоснование". Each has `key`, `title` and `actions` ("реакция" or `null`).
- `more`: the P7 sections of the "**Подробно**" paragraph at the end of the block's own text, `[{doc, key}]`: where and how the hazard comes into play (6.1 for the energy doors, 8.2 for the clock). The paragraph is not part of `body`; a link without a target is a builder error. Without the paragraph `more` is empty.

A missing traits or Stealth line, or no rules subsection, is a warning in the report.

**The "Канон → Опасности" page** (`site/pages/hazards.js`). `#/canon/hazards` is a table of the 12 hazards: traits, level, simple or complex, Stealth and the check ("Рефлекс КС 20", for the lightning circuit "атака +20"), with a filter by name and trait. Below the table are the laws of the world without a block ([P7, section 11](../korabl_vremeni_punkt_7_hazards.md#11.%20Законы%20мира%20без%20блока%20характеристик)) as links to the reader. `#/canon/hazards/<id>` is the card: kind and level, traits as tags with tooltips, the block in a frame, the reactions and routines with a "реакция" tag, the folded "Обоснование", then "Подробно" with the `more` sections folded as on the NPC card, and a link to P7. In the reader every hazard block heading links to its card. The parts shared by creature, hazard and NPC cards live in `site/card.js`, the "Подробно" folds (`More`) among them.


## NPCs

The short NPC and faction cards of [P8, section 20](../korabl_vremeni_punkt_8_fraktsii_i_npc.md#20.%20Карточки%20НПС%20/%20фракций) are parsed by `tools/site_npcs.py`, which the builder calls. A card is a subsection "20.2. Сарежейн" of bullets "- **Поле:** текст". Cards keep different fields (the dead operators have fewer, the family joins some), so the fields are kept as written. The last bullet, "**Подробно:**", links to the full sections: the NPC in P8 and its block in P11 or P9. An NPC in `canon.json` has:

- `id`: the name in Latin letters, also the picture file name; it may match only the `id` of its own creature, and then one picture serves both cards. Any other match is a builder error.
- `doc`, `key`: the card's section; `name`.
- `fields`: the fields in order, `label` and `text` (markdown).
- `more`: the sections from "Подробно" (`doc`, `key`); a link that finds no section is a builder error.
- `creature`: the `id` of the creature whose block or `home` section is one of the "Подробно" sections, else `null`.
- `start`: the room number when the field "Старт" is just a number ("19."), else `null`: the whole ship, not made yet, dead, a group without a place. The GM puts such an NPC on the map by hand.

A card without fields or without the "Подробно" line is a warning in the report.

**The "Канон → НПС" page** (`site/pages/npcs.js`). `#/canon/npcs` is a table of the 11 NPCs and factions: type, start, main goal and the block's level linked to the creature card, with a filter by name and type. `#/canon/npcs/<id>` is the card: the P8 fields in two columns with links and tooltips, the block's level in the header, and buttons to the creature card and to the card itself in P8. Below, "Подробно" folds every section of the "Подробно" line, as the creature card folds its info, titled "П8 · 14.4. … · Сарежейн" (an unnumbered heading gets the path up to the nearest numbered section) with a link to the reader inside; the creature's block section is not folded again. The "Подробно" line in P8 itself gathers every section where the canon writes about the NPC: the site does not look for them by name. A creature card whose block serves an NPC gets an "НПС: …" button back. The picture is `site/img/<id>.*` or, failing that, the creature's picture: so the Cult shows the Paradox Servant. In the reader every P8 card heading links to its card.


## Items

The P12 items with knowledge layers are parsed by `tools/site_items.py`, which the builder calls. The layers block follows the pattern of [P12, section 24.4](../korabl_vremeni_punkt_12_predmety_sokrovishcha_i_ekonomika.md#Блок%20слоёв%20у%20предмета): a "**Слои знаний.**" line with the action, skill and DC, then a table of degrees. The block stands at the end of the item's section or in its last subsection. The item is the nearest section, the block's own or above, whose first line is an item header: "**Категории:** …", "**Категория: …**" or "**Предмет N-го уровня, …**"; a section without one is an item itself. Section 24.4 is the pattern, not an item. The Mechanical Dog and the Posthuman of section 18 are not items: their blocks are for parts of a creature's body, which the canon calls built-in systems and body parts. Their layers go to the `parts` field of the creature of the same name. A missing section is a builder warning, a missing creature an error. An item in `canon.json` has:

- `id`: the name in Latin letters, also the picture file name; it may match only a creature of the same name (the Jaw), and then the picture is shared. Any other match is a builder error.
- `doc`, `key`: the item's section; `group`: its top section ("18. Трофейная технология существ будущего"); `name`.
- `check`: the block's line after "Слои знаний.": action, skill, DC and remarks (markdown).
- `layers`: the table rows in order: `label` (as written, "Успех, Ремесло КС 15"), `degree` ("Без проверки", "Успех", "Критический успех", "Критический провал", "Не узнаётся") and `text`. The `label` keys the players' mark, so a repeated row is a builder error.
- `block`: the section holding the block; `rest`: that section's text without the block, so the card does not show the table twice, and without the "**Подробно**" paragraph.
- `more`: `[{doc, key}]`: the "Общие правила" subsection of the level-2 section above the item (18, trophy technology; 20, the Library), then the links of the "**Подробно**" paragraph in the block's section, where else the canon writes about the item (P5 for the Crystal and the Bracelet, section 25 for the replicator). A link without a target is a builder error.

Two blocks for one item are an error; a block without a table and an unknown degree are warnings.

**The "Канон → Предметы" page** (`site/pages/items.js`). `#/canon/items` is a table of the 29 items in P12 order: how many layer rows the players already know, the check and the P12 section, with a filter by name, section and skill. `#/canon/items/<id>` is the card: first "Слои знаний", the check line and the table with a "знают" mark on every row, then the item as the canon writes it, without the layers table, and "Подробно" with the `more` sections folded as on the NPC and hazard cards. An item that is also a creature (the Jaw) gets a "Существо: …" button, and its creature card a "Предмет: …" one. A mark on the "Критический провал" row means the players believe the false conclusion; that row is coloured.

A mark is party state: the event `item-layer` `{ item, name, row, known }` (slice `itemLayers`), so it goes to the journal, can be undone and shows in every window. A row is keyed by its canon `label`: if the canon rewrites the row, an old mark no longer applies to it. In the reader every item heading links to its card.


## World state

The builder takes the schema of the "Игра → Состояние мира" page from [P2, "Минимальный лист состояния Мастера"](../korabl_vremeni_punkt_2_struktura_i_zavisimosti.md#Минимальный%20лист%20состояния%20Мастера); `tools/site_state.py` parses it. The sheet is a text block: its first line is the sheet title, then come the groups. A group is a line in capitals followed by "Поле: значение" fields. The value sets the kind of the field, as the legend above the sheet says:

- variants joined by " / " are a choice of one (`choice`, `options`);
- a blank of five "_" is a number (`number`, `max: null`), `_____ / 17` a number with a limit (`max: 17`);
- a blank of ten "_" is a short note (`text`, `long: false`), a longer one a list or a log (`long: true`);
- a line that is a blank alone is a free note of the whole group: the field has `label: null`.

A field's `key` is "ГРУППА · Поле", or the group title for the free note; it keys the page's events, so a field renamed in the canon loses its old value. `rooms` are the room numbers in the group title, the label and the variants: the room page will show its fields by them. The table above the sheet gives each group `more`, the P2 sections of part 3 that describe it in full. The subsection under the sheet, "Исходное состояние Корабля", is a table "Группа | Поле | На старте | Откуда": it gives a field its `start` (a variant, a number or a string; `null` without a row, and such a field starts empty) and `source` (the markdown of "Откуда"). The group is written on the first row of its fields; "—" instead of a field is the group's free note. In `canon.json`, `state` is `doc`, `key` (the sheet section), `start_key` (the starting state subsection or `null`) and `groups` in order: `title`, `more`, `fields`.

A value outside the legend, a number outside rooms 1–41, a group without fields or table links, a missing starting state subsection and a start value without a source are warnings; a field written twice, a table group missing from the sheet, a link without a target, and a start value for a missing field, one that does not fit the field or one written twice are errors.

**The "Игра → Состояние мира" page** (`site/pages/world.js`). `#/game/world` shows the sheet's groups as panels, each with links to its P2 sections. `site/masonry.js` lays them out: as many 420 px columns as fit, each next panel going to the shortest column, so the columns end at about the same height. The whole layout is redone when the number of columns or the filter changes; when a panel grows or shrinks, it and every panel before it stay put and only the panels after it are laid out again. A field starts at its canon start value, shown muted, and the tooltip on the field name says where it comes from. A field's control follows its kind: a choice is a row of variant buttons, a number is a field with its limit, a note is a box as tall as its text: one line when empty, otherwise as many lines as the text takes, wrapped ones included. A short note sits next to the field name, a long one takes the panel's width. Before each layout `site/masonry.js` sends a `masonry-measure` event, and the notes fit the new column width before the panels are measured. A field the party changed is highlighted and has an "исходное" button; clicking the marked variant also brings the start back, and for a field without a start it clears the mark. The filter matches the field and group names, and a number also matches the field's rooms: "41" shows everything about room 41.

A change is party state: the event `world-set` `{ field, value }` (slice `world`, keyed by the field's `key`); `value: null` drops the change and the field is back at its start. A value equal to the start is sent as `null` too, and `""` is a note deliberately emptied. Start values are not written to the journal: the canon gives them, so editing the P2 table changes every field the party has not touched. A choice is sent at once, a number or a note when the field loses focus or on Enter (Ctrl+Enter for a long note), and Escape brings the old value back, so the journal gets one entry per change. A number is kept between zero and the field's limit. Values of fields the sheet no longer has (a field renamed in the canon) are listed at the bottom in a block of their own and can be cleared there.


## Rooms

The builder takes the rooms from [P13](../korabl_vremeni_punkt_13_room_by_room_pf2_overlay.md#Комнаты%201–41): the 41 sections "N. Name" under "Комнаты 1–41"; `tools/site_rooms.py` parses them. A room has `number`, `id` (`komnata-N`, the picture name), `doc`, `key` (the P13 section), `title` without the number, and the ties the canon itself writes rather than guessed by name:

- `creatures`, `hazards`, `items`, `npcs`: the card ids from the links of the room's "**Связанные системы:**" line, in the line's order. A link to a section gives every card whose section is that one or lies under it: P9, 22 gives the eleven Warehouse prisoners, P12, 19 the six Museum exhibits; a creature is also found by its NPC section in P11, and an NPC by its card in P8, 20 or a section of its "Подробно" line. A link to a whole file gives no card;
- `neighbours`: the numbers of the rooms the same line links to;
- `start`: the room has the line "**Старт группы:**", the party begins the adventure there ([register, topic 1.15](../otkrytye_voprosy.md#1.15.%20Где%20группа%20начинает%20приключение)). Exactly one room must have it, otherwise it is a builder error;
- `outside`: the room's "**Случайные встречи**" block says the P10 table is not checked or not generated there, so the room is outside the ship's inner space. For now these are the farm (1), the Cellar (2), the Underground River (38) and 41. A block that says something else is a builder warning;
- `fields`: P2 sheet field keys, first those the room's text names in backticks as `ГРУППА · Поле`, then those whose name holds the room's number. A trigger "условие → следствие" may name several fields in one pair of backticks: `ГРУППА · Поле = а + ГРУППА · Поле = б → ГРУППА · Поле = в; …`; a value after "=" ends at ";", ",", "+" or "→";
- `source`: `{ line, parts }` from the [source](../korabl_vremeni_ocr.md), or `null` when the source has no such room; `tools/site_room_source.py` parses it. A part is `{ text }` (the source markdown as written), `{ heading }` (the room's own subheading: for now only the console table in 19) or `{ cut, kind, id, line }` (a pasted card block, replaced by a link). The module's `BLOCKS` table maps "source heading → card"; the source names headings its own way ("Хрустальные пауки" for "Хрустальный Паук"), so the card is written down, not guessed. A creature block runs up to the `**КБ …` line and the list under it; an item block (heading in italics) runs over its italic paragraphs and italic list lines. After a block the room text may go on without a heading.

A field the sheet lacks, a value after "=" the field does not take, a related link without a target, an unknown heading inside a source room and a block with no card are builder errors; a room without the related line, a block whose card the room's related line does not name and a room without a source are warnings. The builder lists the cut blocks in the report as `source_cuts`. `tools/tails_check.py` keeps room flags of their own names (`рост_8_футы`), states in backticks without a sheet field (`веко закрыто`) and unlinked points or rooms in the related line out of P13.

**The "Игра → Комнаты" page** (`site/pages/rooms.js`). `#/game/rooms` is a table of the 41 rooms: how many creatures, NPCs, hazards and items each has (the names in the number's tooltip), how many of its sheet fields the party changed and whether it has a note; the filter matches the title and card names, and a number matches the room's number. `#/game/rooms/<number>` is one room: links to the rooms next by number and to those of its related line; on the left the "Исходник" block (`source`) above the P13 overlay as the canon writes it and the picture `site/img/komnata-N.*`, on the right the cards by kind (creatures and hazards with their level), the GM's note and the sheet fields by group. The fields use the same panels as the world state page (`Group` from `site/pages/world.js`): the same buttons, the same highlight of a change, "исходное" and the `world-set` event, so a field changed in a room is changed on the sheet. Below 1000 px of page width everything goes in one column: the source and overlay first, then the cards, the note and the fields.

The note is party state: the event `room-note` `{ room, text }` (slice `roomNotes`, keyed by the room's number, as the picture is, so a renamed room keeps its note); `text: null` drops the note. Like a long sheet note it is saved when the field is left or on Ctrl+Enter, and Enter breaks the line.

**"Где встречается"** (`WhereFound` from `site/card.js`) are the backlinks: the creature, hazard, item and NPC cards list the P13 rooms whose related line names them, by room number, each linking to the room page. Below them come the P10 random encounter rows whose card names the card in its related line, linking to the encounter card's section; a creature also gets its part, "состав", a scene variant by name or both, and the level the row is available from. The page builds them from `canon.rooms` and `canon.encounters`; `canon.json` has no field of its own for them. A card that neither a room nor an encounter row names says so; there are none now.

## Random encounters

The builder takes the random encounter table from [P10](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md); `tools/site_encounters.py` parses it. In `canon.json` it is `encounters`: `doc`, `key` (section [4.2](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md#4.2.%20Единая%20накопительная%20таблица%201–12) with the table), `cards` (section 12 with the cards), `outside` (section 11, the scenes outside the table), `procedure` (section 2, the checks), `stop` (section 18, the detached ship ends the checks), `levels`, `[{level, die}]` from the table of [section 3](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md#3.%20Принцип%20накопительной%20таблицы): d6 at level 3, d12 at level 4, and `rows`, one per result:

- `number`, `level` (available from), `name`; `composition`, `type`, `chrono`, `repeat`, `reaction`, `signs`, `motive`: the table's columns as written; `count`: the composition die from the start of the "Состав" column ("1d6", "2"), or `null` when the composition is no number (No. 12);
- `key`: the card section "№ N. Название" in section 12;
- `creatures`, `hazards`, `items`, `npcs`, `rooms`: cards and rooms from the links of the card's "**Связанные системы:**" line, resolved as a room's are. The line is split at ";", and a part's text outside its links is its role: "состав" puts its creatures into `main`, the row's usual composition, and "вариант «…»" into the `creatures` of the variant of that name. A part of links only keeps the role of the part before it: "трофеи — [18.1]; [18.2]";
- `variants`: the card's paragraphs "**Вариант сцены — название.** …": `name`, `text` and `creatures`;
- `fields`: the P2 sheet fields the card names as `ГРУППА · Поле`: the smugglers at large for No. 5, the Posthuman for No. 11.

A table row that is not ten columns, a row without a card and a card without a row, numbers out of order, a level die that does not cover exactly the rows available, a related link without a target, an unknown sheet field, a value the field does not take and a variant in a role the card lacks are builder errors; a variant whose creatures the related line does not name and a card named otherwise than its table row are warnings. `tools/tails_check.py` also checks the related line of every card.

**The "Игра → Случайные встречи" page** (`site/pages/encounters.js`; the state and rules are in `site/encounters.js`). The counter follows the turn tracker: a turn in the ship is a step, a noisy turn one more ([P3, section 9](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#9.%20Шум)); while "группа вне Корабля" is on, turns give no steps ([P10, section 2](../korabl_vremeni_punkt_10_sluchaynye_vstrechi.md#2.%20Что%20сохраняется%20из%20исходника)). A check comes every 2 steps, every 4 when the sheet has `СТЫКОВКА 39 / ВРЕМЯ 41 · Кристалл 39 = снят` or `Агрегат 39 = разрушен`; with `ОБОЛОЧКА · Корабль отделён = да` there are no checks. The period is read from the sheet when the dice are rolled and kept in the event, so a crystal removed later does not recount past checks. The page shows the checks due, and so does the sidebar tracker, as a link to the page.

"Бросить проверку" rolls the check d6 and the table die together: d6 or d12 by the party's level (a switch on the page). On a 1 the encounter happened and the site rolls its composition by `count`; otherwise the table die is greyed and does not count as a result. "Бросать до встречи" rolls the checks due in order up to the first encounter, as one event. "Бросали сами" takes the d6, the table die and, if rolled, the composition; with no encounter the table die may stay empty. The row that came up shows its composition with its creatures, signs, motive, scene variants, the other cards of its related line and the sheet fields the card names, in the same `Group` panels as the world state page. The guaranteed echo comes from the queue of "персонаж выбыл" (see "Вы сами"): while someone waits and the snapshot six turns back exists (`echoOf` of `site/encounters.js`), the next check is No. 12 without a roll, "бросить проверку" reads "гарантированное эхо" and typing one's own dice is closed; above the buttons the page says who waits and whether for the snapshot. The old mark "ждёт гарантированное эхо" stays for old saves only: its button shows while the mark is set, and clears it. The table below counts how often each row came up; rows above the party's level are greyed.

All of this is party state, the slice `encounters`: `turns` (moves the counter), `party-level` `{ level }`, `encounter-outside` `{ outside }`, `encounter-echo` `{ pending }` and `encounter-check` `{ period, level, die, rolls: [{ check, row }], count, entered, echo }`: one or more checks, each using up `period` steps; only the last can be an encounter. The journal writes them in words.

## Turn tracker

The sidebar of every page is the turn tracker (`site/turns.js`) of [P3, section 1](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#1.%20Ход%20исследования): the GM marks an exploration turn when about 10 minutes of meaningful activity have passed. The tracker shows how many turns and how much time have passed, the time of day and the time since the last long rest. Buttons: "+1 ход", "шумный ход", "+1 час" (6 turns) and "отдых 8 ч" (48 turns); the tracker's last entry stands under the buttons with an "отменить" button, and Ctrl+Z works too. When random encounter checks are due or the guaranteed echo waits, a link to the encounters page with their number stands under the buttons. Below it stands a hint when the live map disagrees with "группа вне Корабля" (`placeHint` in `site/encounters.js`): the party token and every character token on the map stand in `outside` rooms while the counter runs, or one of them is inside while the counter stands. The hint names the token and the room, and its button sends the same `encounter-outside` as the switch on the encounters page. The site does not switch the counter itself: tokens are optional, and in 41 it matters whether the whole party is there ([P13, 41](../korabl_vremeni_punkt_13_room_by_room_pf2_overlay.md#41.%20Ферма%2054%20года%20назад)). A token off the map does not count.

All of it is party state, slice `turns`:

- the event `turns` `{ count, noisy, rest }`: `count` turns pass. A noisy turn ([P3, section 9](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#9.%20Шум)) is one turn with `noisy: true`; the random encounter counter (`site/encounters.js`) moves one step further for it. `rest: true` is a long rest: by the ruling in [P3, section 4](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#4.%20Типовые%20действия%20и%20стоимость%20времени) it is 48 ordinary turns with the encounter counter, and the time since rest starts again;
- the event `clock-set` `{ start, at }`: the time of day. The canon gives no hour of arrival, so the GM sets it by entering the time "now"; the time at turn 0 is kept, in minutes from midnight of day 1 (the day the party arrives), so every later turn moves the clock. `at` is the time entered, for the journal; `start: null` clears the time of day. A new time changes only the hour and minute: the day stays the same.

The time field is saved when it is left or on Enter; Escape brings back the previous one.

## Scene

The "Игра → Сцена" page (`site/pages/scene.js`, state in `site/scene.js`) runs one fight: who is in it, the initiative order, each instance with its own hit points and conditions. The numbers (AC, HP, saves, initiative modifier) come from the canon card; the instances are party state. A creature or hazard is added by the suggesting field on the page (several at once, too), by the "В сцену" button of a creature or hazard card, by the "в сцену" button at them in the cards of a room page (one more instance each click), and by the "в сцену" button at the composition of a rolled random encounter (one instance of each). The party's characters are added by the buttons "Партия: …" and "вся партия" on the page and by "в сцену" on "Вы сами"; in the scene a character has the AC and saves of the import, and the hit points and conditions of "Вы сами": the row sends the party's events (`pc-hp`, `pc-condition`), and the scene keeps no copy. Players roll their own initiative: a character has no modifier, "Бросить инициативу" skips them, and the GM types the result. Anyone else without a card is added by name, for the initiative order only. A second instance of the same name is numbered: "Пёс", "Пёс 2"; a character keeps its name.

"Бросить инициативу" rolls d20 + Perception (Stealth for a hazard) for everyone without initiative yet, as one event; the initiative field can be filled by hand too. The order is by initiative, highest first; ties and those without initiative go in the order they came in. "Начать бой" / "Следующий ход" move the turn marker and the round counter; the button sends the turn it sees, so a double click skips no one. Damage and healing keep hit points between 0 and the maximum, and a combatant at 0 HP is dimmed. Conditions come from the glossary, with the hover tooltip; a condition with a value has "−" and "+" buttons, and choosing it in the list again adds 1 too.

Slice `scene`, events (each carries the names the journal writes):

- `scene-add` `{ list: [{ kind, ref, name, max, mod }] }`: `kind` is `creature`, `hazard`, `pc` (a character of the party, `ref` its id, `max` and `mod` `null`) or `other`; an instance gets id `<seq>.<n>`; the journal writes equal names once with their number: "вошли Хрустальный Паук ×3";
- `scene-hp` `{ id, name, delta }`, `scene-init` `{ list: [{ id, name, value }] }`;
- `scene-condition` `{ id, name, condition, value }`: the condition name without " N"; `value` is a number, `true` for a condition without a value, `null` takes it off;
- `scene-remove` `{ id, name }`: when the one whose turn it is leaves, the marker goes to the one before, and the round goes on;
- `scene-turn` `{ id, name, round }`, `scene-clear` `{}`: "Завершить сцену" empties it (undone like any action).

## Map

The builder takes the map graph from [`karta_graf.json`](../karta_graf.json), traced over the paper map with `tools/karta_trace.html` (see [the ship map, 4.1](../karta_korablya.md#4.1.%20Граф%20карты)); `tools/site_map.py` parses it. The builder does not change the graph, it only checks it and makes it ready to draw. In `canon.json` it is `map`:

- `doc`, `key`: the site section whose text links to `karta_graf.json` (now "4.1. Граф карты"), found by the link, not by its title;
- `box`: `[x, y, width, height]`, the frame of all points with a margin of 60, in tracer coordinates;
- `types`: the passage types in the file's order: `id`, `title` (as in the file), `count`;
- `nodes`: the rooms (points with `room`): `id`, `x`, `y`, `room`. The other points are corridor bends, needed only as ends of passages. The builder leaves out the tracer's notes on points and passages: they were written to check the tracing, not for the game;
- `edges`: the passages: `id` (the live map finds the flicker walls and the changes by it), `type`, the end points `a`, `b`, their coordinates `x1`, `y1`, `x2`, `y2`. Every point of the graph is an end of some passage, so a new passage snaps to the points found among the ends;
- `points`: how many points the file has in all;
- `start`: the room where the party begins (the P13 room with `start`);
- `photo`: the photo of the paper map the graph was traced over: `src` (its copy in `site/data/`), `file` (the source file), `width` and `height` of the file and `transform`, the SVG matrix that turns the photo by the graph's `image.rotation` and scales it into the graph's frame. It is the photo of `tools/karta_analyze.py` (the `PHOTO` constant), so the script's overlay and the site's underlay match. The server serves only `site/`, so on every data write the builder puts a copy of the photo at `site/data/karta_foto.jpg`; like `canon.json`, it is not kept in git. The copy goes without its EXIF block: the photo has an orientation tag, a browser would turn the photo by it, and the matrix, like `karta_analyze.py`, works on the pixels as stored. Without the photo it is `null`.

A missing or unreadable file or a format other than `karta-trace/1` is an error, and `map` is `null`. A repeated point or passage id, a passage to a point that does not exist and a passage of an unknown type (the passage is skipped), a room number P13 lacks and a start room of the party or of an NPC without a point on the map are errors; a P13 room without a point, a graph no section links to, a photo that is missing or does not read as JPEG and a photo whose shape does not fit the graph's frame are warnings. The builder report counts `map`: `{ nodes, edges }`.

**The "Игра → Карта" page** (`site/pages/map.js`). `#/game/map` is the whole graph, `#/game/map/<number>` the same with the room marked; a number not on the map is said so. The graph fits the screen under the top bar whole, without zoom or scrolling: as tall as the screen, as wide as the graph frame's proportion allows (`--map-ratio`). To the right stands a column of the passages that matter in play, scrolling on its own: flicker walls, secret doors, locked and special passages. Each passage in the column has its number and the rooms on both sides ("№ 643 16 — 4"): the end of a wall is usually a bend of a corridor, so the room is found by a walk along corridors and doors (`sidesOf` in `site/pages/map_edit_panel.js`; it also labels passages in tooltips and changes). A click on a number puts a halo on the passage on the map, a second click takes it off; while the pointer is over a row of the column, its passage has a halo too.

**The passage popup.** A click on a flicker wall, a secret door, a locked or a special passage on the map picks it in the column and opens a popup at the point clicked: the passage's label and the same as its row, the wall's state and buttons, the "найдена" mark of a secret door; locked and special passages have no state, and the popup only names them. The popup stands to the right of and below the point if it fits, otherwise to the left or above, and always inside the map's frame: it is measured after every draw, as its width follows the state it shows (`place` in `site/pages/map.js`). The cross, Escape, a click on the map away from the passages, a second click on the same passage and a change or token mode close it. When the page is too narrow to leave the map ~700px, the column goes under the map (a container query on the page's width). Rooms are circles with their number; a click opens the room page, the tooltip gives the number and the P13 title. Lines are the passages. Each passage type is a layer with a checkbox, a colour and a count; the colours are the `--edge-<type>` variables of `style.css`. Corridors and open passages (276 of the 333 lines, and the photo shows them anyway), secret doors and special passages start hidden. A passage of a hidden layer still shows while it has a halo: picked, or under the pointer in the column. The map opens from the "Игра" navigation, from the "Карта Корабля" link of the sidebar and from the "На карте" link of a room page. The layers, the photo, the legend, the tokens and the map changes are under the map. Under the graph lies the photo of the paper map (`map.photo`) at full brightness, with its own checkbox "Фото карты" (on) and a slider to dim it. The layers, the photo and the picked passage are the page's view, not party state: they do not go to the journal.

**Flicker walls** ([P5, section 6](../korabl_vremeni_punkt_5_fundamentalnye_sistemy.md#6.%20Мерцающие%20Стены)). The walls are the graph's passages of type `flicker`; a wall is named by its passage `id` ("№ 643"). `site/walls.js` keeps the state (slice `walls`), the panel in the column next to the map is in `site/pages/map.js`. A wall exists, is absent or is unknown (never rolled). The roll is lazy, as in P5, 6.2: a tracker turn rolls nothing, it marks "нужен бросок" on every known wall not in view. A wall is rolled from its row, or all the due ones at once in one event. A wall in view keeps its state over any number of turns; whether the party sees it is the GM's call, so the "на виду" mark stays until taken off. The GM can set a state by hand: real dice, or a taken volume where a wall does not appear (P5, 6.6). The sheet field `ХРУСТАЛЬ · Мерцающие Стены стабилизированы` sits on the panel with the same buttons as on "Состояние мира": at "да" turns leave the walls alone, a known wall keeps its state for good, and an unknown or due one is rolled once more, for good (P5, 6.10). A row of the column does not write the state in words: it is the lit "существует" or "отсутствует" button, faded with a dashed border when a roll is due, and then "бросить" is lit; an unknown wall has neither lit. The popup on the map also names the state in words. Shift with a click on a wall on the map or on its number in the column adds it to the picked walls or takes it out; while more than one is picked, the top of the column under the change block shows "Выбрано стен: N" with "на виду", "не на виду" (one `wall-seen` event for all), "бросить нужные" (one `wall-roll`) and "снять выбор". Escape with no popup open and a click on the map away from the passages drop the pick too. On the map an existing wall is a solid line, an absent one dashed, an unknown one grey dots, a due one faded, a wall in view has a halo. Every wall is listed in the column. A click on a wall on the map picks it: its row is highlighted and scrolled into the column; a click on a number in the column shows the wall on the map. The "Правила" link goes to the parent of the field's source section (P5, 6.8 → P5, 6); the page code holds no section key.

Events:

- `wall-roll` `{ list: [{ id, exists }] }`: 50% rolls of the site, one wall or several;
- `wall-set` `{ id, exists }`: a state set by the GM;
- `wall-seen` `{ list: [id], seen }`: walls come into or out of the party's view;
- the slice also listens to `turns` (a turn boundary) and to `world-set` of the stabilization field. The sheet starts at "нет", so a dropped change (`value: null`) is "нет" too.

**Secret doors** ([P3, section 5](../korabl_vremeni_punkt_3_protsedura_issledovaniya.md#5.%20Поиск%20и%20скрытые%20проходы)). The graph's passages of type `secret`, two of them: 20 — 21 and 2 — 38. Whether the party found one is the GM's mark "найдена" in the column, like "на виду" of a wall; the P2 sheet has no field for it, it is party state. `site/secrets.js` keeps it (slice `secrets`). On the map a door not found is dashed, a found one solid, its state in the tooltip.

Events:

- `secret-found` `{ id, found, label }`: the door is found or the mark is taken off; `label` is the passage's label for the journal.

**Locked and special passages** (`locked`, `special`) are listed in the column without a state of their own: number, rooms, type.

**Map changes** ([P5, 4.6 and 4.11](../korabl_vremeni_punkt_5_fundamentalnye_sistemy.md#4.11.%20Карта)). Direct changes of the world, made by the Bracelet, result 6 of the control room console or plain tools. They are not a phase, so a change holds in view of the party and over the stabilization of the walls (P5, 6.1 and 6.11), and never goes back by itself. `site/map_edits.js` keeps the state (slice `mapEdits`), the map changes are `site/pages/map_edit_panel.js`: at the top of the column next to the map, the "Правка карты" block with the three modes (`EditBar`, it stays on top while the column scrolls); at the end of the column, "Правки карты", the list of changes made (`EditList`). Three kinds:

- "Мерцающая стена убрана навсегда": the wall no longer flickers or rolls, the passage is open. A faint grey line on the map, "убрана навсегда" in the walls panel;
- "Переход закрыт": crystal grew over the passage; the passage fades, with a cross in the middle;
- "Новый проход": two clicks on the map. An end snaps to the nearest graph point within 40 units, otherwise it stays where clicked, in solid crystal. A dashed line in its own colour (`--edge-new`), shown with any layers.

While a change mode is on, a click on the map picks the target instead of opening the room; possible targets are highlighted. A mode with its target also starts from a passage popup: "убрать навсегда…" for a flicker wall, "закрыть переход…" for a secret door, a locked or a special passage; the column block gives the cause, the note and "Применить". "Отмена" turns the mode off. A change has a cause (the Bracelet, the console, for a flicker wall only, or other) and an optional note. "Снять" puts the graph back as it was there; a wall brought back gets the state it had.

The map is the record of these changes. The sheet field `ХРУСТАЛЬ · Изменённые стены/двери` stays for what the graph cannot show (growths, the shape of a room); "Состояние мира" lists the map's changes under it with a link to the map.

The first structural use of the Bracelet sets `ХРУСТАЛЬ · Браслет уже активирован` and `ХРУСТАЛЬ · Мерцающие Стены стабилизированы` (the trigger of P13, room 11, by P5, 6.8). A change with the cause "Браслет" while "активирован" is not "да" sends two `world-set` events right after it. Each is undone on its own; a field already at "да" is left alone.

Events (each carries the words the journal writes):

- `map-edit` `{ kind, cause, label, note? }` and by kind: `wall-gone` and `closed` `{ edge }`, `passage` `{ x1, y1, x2, y2, a, b }`, where `a`, `b` are graph points or `null` for solid crystal. The change's `id` is the seq of the event. A second change of the same passage is not recorded: it is a double click;
- `map-edit-drop` `{ id, label }`: the change is taken back.

**Tokens.** Where the party and the NPCs are, by room. `site/tokens.js` keeps the state (slice `tokens`), the panel "Токены" is `site/pages/map_token_panel.js`. The canon's tokens:

- "Группа" stands in the start room (`map.start`, room 1);
- every NPC of the P8 cards whose field "Старт" names a room stands there (`npc.start`: Sarezhein 19, the Cousin 24, the Dog 32). The other NPCs (the Time Ship, the Lady, the Master and others) are not listed: the GM puts one on the map from the panel's "Поставить НПС…" list, it appears in the party's room and stays listed from then on, even off the map (`offMapNpcs` in `site/tokens.js`).

The GM adds tokens by name: a character when the party splits, or anyone else; such a token appears in the party's room. On the map a token is a mark with initials under its room, coloured by kind (the party and characters, NPCs, other), its name in the tooltip; the room's tooltip lists who is there. A click on a mark, on the map or in the panel, picks the token, and the next click on a room moves it there; a second click on the mark drops the pick. In the panel every token also has a list of rooms. A canon token has an "исходное" button, an added token can be deleted. Moving is a mode of the same map as the changes: picking a token turns off the change kind, and back.

Events (each carries the name for the journal):

- `token-move` `{ id, name, room }`: `room: null` takes the token off the map. `id`: `party`, `npc:<NPC id>` or the seq of the event that added the token;
- `token-add` `{ name, kind, room }`: `kind` is `character` or `other`;
- `token-remove` `{ id, name }`: an added token is deleted; a canon token only goes off the map.

## Milestones

The builder takes the milestone catalog and the level-up thresholds from [P14](../korabl_vremeni_punkt_14_progression_i_temp.md); `tools/site_milestones.py` parses them. It finds the sections by title, with no number in the code. In `canon.json` it is `milestones`:

- `doc`; the keys of the sections the page links to: `catalog` (4), `scheme` (3.4), `readiness` (3.5), `package` (3.7, the causal package rule), `paths` (5.2), `fallback` (5.3), `procedure` (14);
- `categories`: `[{name, measures}]` from the table of [3.2](../korabl_vremeni_punkt_14_progression_i_temp.md#3.2.%20Категории); `scales`: the scale labels of the list in [3.3](../korabl_vremeni_punkt_14_progression_i_temp.md#3.3.%20Масштаб%20условия), weakest first;
- `levels`: `{from, to}` from the heading "3 → 4" under 3.4; both levels must be in the level table of random encounters;
- `knowledge`: the category that is only knowledge, from the rule "Только знание — условия категории «…»" in 3.4 ([register, topic 1.16](../otkrytye_voprosy.md#1.16.%20Какие%20вехи%20—%20только%20знание));
- `fallback_rule`: `{conditions, categories, strong}` from the bold rule of 5.3 "**3 условия, минимум 2 категории, хотя бы одно стратегическое или крупное**"; `strong` is the scales the rule names;
- `crash`: the `id` of the milestone the primary threshold needs, taken from the words "засчитана веха «…»" in 5.2;
- `readiness_items`: the three conditions of readiness for the finale, the numbered list of 3.5, as markdown;
- `paths_items`: `[{id, name, claim, step}]`, the rows of the table in 5.2: the path, how the claim sounds, when the first irreversible step counts;
- `items`: the 23 conditions of the catalog, the sections "Название: условие" of section 4: `id` (Latin, from the name), `name`, `goal`, `key`, `category`, `scale`, `once`: the lines "**Категория:**", "**Масштаб:**", "**Однократность:**" without the dot.

The catalog is checked against the summary table of [section 15](../korabl_vremeni_punkt_14_progression_i_temp.md#15.%20Итоговая%20таблица%20условий%20вех), the same names, categories and scales, and against the names of the table in 3.8. A missing section, a category or scale not from 3.2 and 3.3, a mismatch with a table, a table row with the wrong number of columns, a rule that does not read and a level not in the encounter table are builder errors. The P14 sections outside the milestone cards go to the "not shown on cards" list of the build report.

**The page "Игра → Вехи"** (`site/pages/milestones.js`, state and thresholds in `site/milestones.js`). On top: the party level and both thresholds of 3 → 4, item by item. The primary one: the milestone `crash` is marked, and at least one path is claimed with its first step made. The fallback one: the count of conditions and categories against `fallback_rule`, and at least one condition of a scale in `strong` outside the category `knowledge`. When a threshold is met, the page says "готово и ожидает применения" and offers "применить повышение": it sends `party-level` `{ level: 4 }`, the same event as the level switch of the encounter page. There is no level-up state of its own: "applied" means the party is at level 4 already, so the pages never disagree. Below: the table of paths from 5.2 with "claimed" and "step made" for each (paths do not exclude each other), the development register (the milestones reached, in order, with their level, a note of the world state and "снять"), the three conditions of readiness for the finale and the catalog by category with a search. A catalog entry unfolds into its P14 text, its once-only line, a link to the causal package rule and a field "what is true in the world now" with "отметить". The GM sets every mark: the P2 sheet does not hold whether a claim was made at the table.

All of it is party state, the slice `milestones`:

- `milestone-mark` `{ id, name, level, note }`: the condition is reached at the party level of that moment; `note` says briefly what is true in the world now (the development register, [P14, 14](../korabl_vremeni_punkt_14_progression_i_temp.md#14.%20Краткая%20Мастер-процедура%20повышения%20уровня), step 3). The same condition is not marked twice;
- `milestone-drop` `{ id, name }`: the mark was a mistake;
- `milestone-path` `{ id, name, what, on }`: `what` is `claimed` (the path is claimed) or `made` (its first irreversible step is made);
- `milestone-ready` `{ index, on }`: a condition of readiness for the finale, by its index.

The journal writes them in words.

## Pathbuilder import

The party's characters are party state, not canon: the players send a Pathbuilder 2e export before the first game and after the level-up to 4 ([the player's book](../kniga_igroka.md)), and the export enters the log as an event. The slice `party` and the export parser are `site/party.js`; the page is "Инструменты → Импорт из Pathbuilder" (`site/pages/pathbuilder.js`).

- **Parsing** (`fromPathbuilder`) takes from the export's `build` the name, class, level, ancestry, heritage, background, size and speed; the spell slots from `spellCasters[].perDay` (ranks 1 and up; cantrips are not counted), the focus points and the names of focus spells; weapons, armor, equipment with quantity, and money. It derives the numbers by the core rules: HP = ancestry HP + bonus + (class HP + per-level bonus + Constitution modifier) × level; AC is `acTotal.acTotal`; saves and Perception are the proficiency rank + level (if trained) + the modifier. The export gives item bonuses, runes and feats (Incredible Initiative, say) in no form the site reads, so the GM checks the numbers before the import: `derived` is what was computed, `numbers` what the GM kept; a changed one is marked.
- **Consumables.** Pathbuilder does not mark them. An equipment row the GM ticks becomes a counter with the export's quantity; the first ticks of a new character are a guess by name (potions, scrolls, talismans, ammunition and so on). Own counters are what the export lacks, such as a thaumaturge's temporary talismans.
- **Re-import.** A file of a character already in the party (by name) offers to update them: the build and counters change, the rest of the character's state stays, the quick fields of substep 19c and the damage taken among them. The consumable ticks come from the earlier import. When the character's level differs from the party level, the page says so.

Events of the slice `party`:

- `pc-import` `{ id, build, counters }`: `id` `null` is a new character, whose `id` is the event's number; otherwise an update; `counters` is `[{ name, max }]`;
- `pc-remove` `{ id, name }`: a mistaken import. A character who drops out is not removed: that is "персонаж выбыл" of substep 19f.

The journal writes them in words.

## "Вы сами"

The page "Игра → Вы сами" (`site/pages/yourselves.js`) holds the party's quick fields, which the echo of the "Вы сами" encounter is restored from ([P6, 9.4](../korabl_vremeni_punkt_6_temporal_paradox.md#9.4.%20Восстановление%20состояния%206%20ходов%20назад)). Each character shows AC, saves and Perception of the import, hit points with a damage and healing field and temporary hit points, conditions from the glossary, spell slots by rank and focus points ("осталось N из M", −1 and +1), a "ежедневная подготовка" button, consumable counters and a note of what the character carries and knows. A character at 0 HP is marked; the GM sets "без сознания" and "умирает" by hand. The hit point and condition fields are the scene's components (`HitPoints`, `Conditions` of `site/pages/scene.js`), given handlers instead of scene events.

The quick state lives next to the build, in the slice `party` (`site/party.js`): `damage`, the damage taken, not the current hit points; `temp`; `spent`, what is used, under the keys `slot|<class>|<rank>`, `focus` and `counter|<name>`, not what is left; `conditions`; `note`. So a new build on re-import keeps them: a character with 37 damage has 9 HP after a level 4 import with 46. Events:

- `pc-hp` `{ id, name, delta }`: damage (negative) takes the temporary hit points first; hit points stay within 0 and the maximum;
- `pc-temp` `{ id, name, value }`: temporary hit points, 0 takes them off;
- `pc-spend` `{ id, name, what, key, label, delta }`: used (`delta` > 0) or given back; `what` is `slot`, `focus` or `counter`; `label` is how the journal names it; the amount used stays within 0 and the limit;
- `pc-condition` `{ id, name, condition, value }`: as `scene-condition`;
- `pc-note` `{ id, name, text }`: `null` clears the note;
- `pc-prepare` `{ id, name }`: daily preparations: slots and focus come back, hit points and counters do not; the GM sets them.

**Snapshots** are not events: the slice `party` counts the tracker's turns (`turns`) and, when the count reaches turn k, copies the party as the snapshot of turn k, the state at the start of that turn. It keeps turns N − 6 to N, N being the turn now: the page shows the six before it, and the start of this turn is what "персонаж выбыл" of substep 19f needs. The snapshot of turn 0 is taken at the first turn of the tracker: before it the party is only being imported. Undo and a loaded save rebuild the snapshots like any state, and a mistaken import (`pc-remove`) leaves them too. The page's "Снимки" section has the buttons "−1" … "−6", the snapshot as a table (HP, conditions, slots and focus, consumables, note) and marks the cells that differ from the party now; hovering shows the value now.

**Random encounter No. 12.** When a check comes up No. 12 and it is not the guaranteed echo, the slice keeps the snapshot six turns before it with that check (`echo12`: `{ check, from, list, rolls }`), so later turns do not push it out. Under the encounter card the encounters page shows that snapshot and a button rolling d8 for each ([P6, 9.5](../korabl_vremeni_punkt_6_temporal_paradox.md#9.5.%20Изменение%20состава)): on 1 the character died in the other branch; all dead means a failed echo, and so does no snapshot ([P6, 9.3](../korabl_vremeni_punkt_6_temporal_paradox.md#9.3.%20Какая%20версия%20используется)). Hirelings and companions without a sheet are rolled for at the table. The event is `echo-d8` `{ check, rolls: [{ id, name, roll }] }`.

**The guaranteed echo** ([P6, 10.8](../korabl_vremeni_punkt_6_temporal_paradox.md#10.8.%20Гарантированное%20эхо), [register, topic 1.17](../otkrytye_voprosy.md#1.17.%20Когда%20гарантированное%20эхо%20не%20может%20прийти%20на%20ближайшей%20проверке)). The card's button "персонаж выбыл" asks for a reason from the "Условие" of 10.8 and puts the character in the queue; they stay in the party marked out, their card says whether and what they wait for, and offers "отменить выбывание". While there is no snapshot six turns back, the checks go as usual; then each check brings one echo, in the order of dropping out. The echo comes from the snapshot six turns before the check but no later than the turn of dropping out; the queue keeps the snapshot of that turn itself, since the ring may have pushed it out. Under the check the encounters page shows the survivor with the penalty (half the maximum hit points rounded down and wounded at least 1, the rest as in the snapshot), a reminder of memory, binding and duplicates from the body, and "эхо присоединилось". The one who came back wears "эхо Корабля" with a "закрепить" button: the Shell with control lifts the binding to the crystal walls ([P8, 9.6](../korabl_vremeni_punkt_8_fraktsii_i_npc.md#9.6.%20После%20получения%20управления)). Events:

- `pc-out` `{ id, name, reason }`: dropped out; into the queue (`queue`: `[{ id, name, turn, seq, atDrop }]`);
- `encounter-check` with `echo: true` takes the head of the queue into `arrived`: `{ check, id, name, from, pc, joined }`; an empty queue gives `{ check, id: null }`;
- `pc-echo-join` `{ check, id, name }`: the character takes the echo's state, `out` is cleared, `echo` is `{ anchored: false }`;
- `pc-echo-anchor` `{ id, name, anchored }`.

## Temporal doubles

The page "Игра → Временные дубли" (`site/pages/doubles.js`) is the registry of items that have versions from different times ([P6, 6](../korabl_vremeni_punkt_6_temporal_paradox.md#6.%20Временные%20дубли%20предметов)). Items only, as section 6 of P6 and the P2 sheet field "Временные дубли": versions of characters are the "Вы сами" page. The GM enters an object, its name and, for a canon item, a link to its P12 card, and its versions with the fields of [P6, 6.7](../korabl_vremeni_punkt_6_temporal_paradox.md#6.7.%20Отслеживание%20происхождения): era, personal order on the world line (1 the earliest; equal numbers are versions that cannot be ordered, [7.9](../korabl_vremeni_punkt_6_temporal_paradox.md#7.9.%20Какой%20экземпляр%20остаётся)), how it came to this time, who of the party carries it and where it is, and the marks "in a closed opaque container" ([6.6](../korabl_vremeni_punkt_6_temporal_paradox.md#6.6.%20Закрытые%20контейнеры)), "temporal residue" and "thing of an echo" ([9.8](../korabl_vremeni_punkt_6_temporal_paradox.md#9.8.%20Обмен%20предметами)). An object is "Объект-N", a version "В-N", as in the record of [15.5](../korabl_vremeni_punkt_6_temporal_paradox.md#15.5.%20Предметы).

Pairs are not stored: the page derives them from the live versions of the object in the order of [topic 1.18](../otkrytye_voprosy.md#1.18.%20Три%20детали%20коллапса%20временных%20дублей): the earliest with each later one, then the second with each later one. A version that is gone ("исчезла", "уничтожена", "история переписала") stays in the table, marked with the turn and without pairs; "вернуть" undoes that entry. A new version brings new pairs ([7.6](../korabl_vremeni_punkt_6_temporal_paradox.md#7.6.%20Когда%20возможна%20новая%20проверка%20коллапса)). A character removed from the party stays the carrier under their name, marked "нет в партии".

"Совместно наблюдались" sits on a pair, or on the object when several versions are seen together ([P6, 7](../korabl_vremeni_punkt_6_temporal_paradox.md#7.%20Процедура%20коллапса%20временных%20дублей)). The GM marks which versions are seen; a version in a closed container takes no part. The unchecked pairs come one at a time in the order of topic 1.18: "бросить d100", "бросить до конца" or "бросали сами" with the d100 typed in; 1-50 is a collapse. Each pair is its own event, so undo and the journal go pair by pair. "Устойчиво" stays with the pair for good, even if a version left and came back; a new version brings a new unchecked pair ([7.6](../korabl_vremeni_punkt_6_temporal_paradox.md#7.6.%20Когда%20возможна%20новая%20проверка%20коллапса)). A collapse leaves the version later in personal order; equal order is the site's 50/50 or the GM's choice after a roll at the table ([7.9](../korabl_vremeni_punkt_6_temporal_paradox.md#7.9.%20Какой%20экземпляр%20остаётся)); the vanished version is gone with reason "коллапс", its pairs drop without a roll and the survivor goes on. "Проверки коллапса" under the object keep every check ([7.10](../korabl_vremeni_punkt_6_temporal_paradox.md#7.10.%20После%20коллапса)); a collapse shows the centre of the discharge (the survivor's place at the collapse), the P7 card "Разряд коллапса временных дублей" and "В сцену".

The registry shows on other pages too. Under the field "Временные дубли" of the P2 sheet, on "Состояние мира" and on the pages of rooms 39 and 41, is its summary: per object the live versions with their place, the pairs (stable and unchecked), the collapses, and a line about the Cult's +1; the field's note stays for what old saves wrote there. The card of encounter No. 10 "Служители Парадокса" tells whether the first undetermined reaction roll gets +1 ([P8, 10.4](../korabl_vremeni_punkt_8_fraktsii_i_npc.md#10.4.%20Отношение%20к%20путешественники%20во%20времени%20и%20дублям)): a pair checked as stable whose versions both exist and one of them is carried by a character of the party who has not dropped out gives it (`cultPairs`). The guaranteed echo that arrived reminds the GM to enter the echo's things in the registry marked "вещь эха" ([P6, 9.8](../korabl_vremeni_punkt_6_temporal_paradox.md#9.8.%20Обмен%20предметами)).

The slice `doubles` (`site/doubles.js`): `{ objects, count }`; an object is `{ id, number, name, item, note, versions, count, checks }`, a version the fields below with `id`, `number` and `gone`: `null` or `{ reason, turn, seq }`, plus `into`, the survivor's label, for one gone in a collapse. A check in `checks` has the fields of its `double-check` event with the pair's `key` and `seq`. Events:

- `double-object` `{ id, number, name, item, note, changed }`: a new object (`id: null`, its `id` is the event's number) or new fields; `item` is the `id` of a `canon.items` entry or `null`; `changed` names the edited fields for the journal;
- `double-object-remove` `{ id, number, name }`: the object was a mistake;
- `double-version` `{ object, id, number, name, label, fields, changed }`: a new version (`id: null`) or new fields; `fields` are `era`, `order`, `origin`, `carrier` (`{ id, name }` of a character or `null`), `where`, `hidden`, `residue`, `echo`;
- `double-version-gone` `{ object, id, number, name, label, reason, turn }`: the version is gone at that turn of the tracker;
- `double-version-remove` `{ object, id, number, name, label }`: the version was a mistake;
- `double-check` `{ object, number, name, a, b, pair, roll, entered, result, survivor, vanished, tie, at, turn }`: the collapse check of the pair of versions `a` and `b` (`pair` is "В1 ↔ В2"): `roll` is the d100, `entered` when the GM typed it; `result` is `"stable"` or `"collapse"`; on a collapse `survivor` and `vanished` are `{ id, label }`, `tie` is `null` or `{ entered }` for equal order, `at` the survivor's place, the centre of the discharge; otherwise they are `null`.

## Journal

The page "Игра → Журнал" (`site/pages/journal.js`) lists every event of the save in words, newest first: the entry number, the exploration turn it came on (the sum of the `turns` events in force before it), the time and what was done. `describe` gives the words: each slice has its own function such as `sceneText`, and a new kind of event is added there. An undone entry stays, struck through; an undo row says what it undid or brought back.

- **Search** goes over the entry's words, its number and its comment, ignoring case and "ё"; every word of the query must be found. Checkboxes: "отменённые и отмены" (off: only entries in force) and "только с комментарием". The first 100 found are shown, then "Показать ещё".
- **Undo from the page.** "отменить" on an entry in force, "вернуть" on an undone one: it undoes the undo that cancelled it. Undo rows have no buttons of their own. "Отменить" and "Вернуть" above the list are Ctrl+Z and Ctrl+Shift+Z.
- **Notes and comments.** A Master note is a row of its own. A comment belongs to a row and sits under it: "комментарий", "изменить", "убрать"; Enter saves, Escape leaves it as it was. Editing a comment is an event, Ctrl+Z undoes it, but it is not shown as a row, so there are fewer rows than entries in the top bar, and the page says how many fewer.

Events: `note` `{ text }` (slice `notes`) and `journal-comment` `{ target, text }` (slice `comments`: entry number → text; the last one in force wins, `text: null` takes the comment away). The page "Инструменты → Сохранения" shows only the save and its files.

## Pictures

The pictures, illustrations from the source book, live in `site/img/` and are kept in git. A picture goes to a card when its file name matches the card id; the extension is any of `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.svg`. The site asks the server for the list (`GET /api/images`) each time a card opens, so a new picture shows up without a restart. Without a picture the card tells the file name to use.

- **Names.** A creature or an NPC: the name in Latin letters by the builder's rule ("Хрустальный Паук" → `khrustalnyy-pauk`); an NPC with a stat block has the same id, so one picture serves both cards. A hazard or an item: the same, by its name. A room: by its number, `komnata-4`, `komnata-19`, so renaming a room does not detach its picture.
- **Layout** (`site/pictures.js`). The files are cut to different sizes, so a picture is placed by its proportions: a strip (height at least 1.8 times the width) as a narrow column on the right, a banner (width at least 1.8 times the height) across the whole width above the description, others on the right. With a picture the card is wider by its column (up to 1120 px): the block and the text run beside the picture and take the whole width below it; without one the card keeps the reading width. A narrow card (up to 720 px) has no room beside a picture and its tables would drop below it, so there every picture stands above the text, up to 260 px high. On a card a picture is never stretched beyond its size. A click opens it over the whole window; a click or Escape closes it.
- **Schemes in the canon.** A scheme to a rule is not a card but part of a section: the canon markdown writes it as an image, `![Состояния Ока](site/img/oko-sostoyaniya.jpg)`, with the path from the repository root. Both Obsidian and the site reader show it (`site/markdown.js`; the `site/…` path becomes the site address): centred in the section, up to 480 px high, a click opens it over the whole window. The file name is free but must not match a card id.
- **"Инструменты → Картинки"** lists every file with its size, layout and the card or scheme section it belongs to, or "не подключена"; below are the cards without a picture and the file name each expects. A new kind of card is added to `pictureOwners` in `site/pictures.js`.

## Keeping state on a page

A page describes its part of the state as a slice and changes it only through events:

```js
import { defineSlice, dispatch, getState, useStore } from "../store.js";

defineSlice("notes", () => [], {
  note: (notes, data, event) => { notes.push({ seq: event.seq, text: data.text }); },
});

dispatch("note", { text: "The party went down to the Cellar" }); // sent to the server
const notes = useStore(() => getState().notes);                  // re-renders by itself
```

The state is rebuilt from the log on every change, so a handler edits a fresh slice and keeps nothing between calls. Undo, redo and window sync work for every slice with no extra code.
